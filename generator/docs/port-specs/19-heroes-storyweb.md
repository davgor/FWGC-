# Port specification: 19-heroes-storyweb

Extracted from the Python `FantasyWorldGenerator` at commit `b67c99b` before that
repository was retired, then audited against the same source by a second reader.

**Source modules**

- `Sim/hero_generator/`
- `Sim/story_web/`

**Estimated C++ size:** roughly 6500 lines, excluding tests.

## Audit: NOT YET IMPLEMENTABLE

The spec's algorithm, ordering-hazard and constant coverage is genuinely strong — I re-derived A3-A33 and B0-B10 against the source and the loop structures, tie-breaks, seed-domain strings, roll formulas, wells.json/alignment.json/weights.json/constraints.json values, the 32 archetype ids with their drift/intensity/faces flags, the 51 trope ids and the pipeline call order are all correct, and the preserved rationale (the countryside anchor, floor(x+0.5), the villain:prior_age disclaimer, the pressure exemption) is carried faithfully. It nonetheless fails the test set for it, for two reasons. First and decisively, it is a spec for the CODE and not for the DATA: five of the eight policy documents are the subsystem's actual output content — 32 archetype cards' belief/wants/fears/tells/mechanic/never/pole_notes/lines prose, six axis-overlay entries, every epithet template and cover role, and 51 tropes x 3 acts x 317 options of prompts, completions and effect tags — and the spec quotes one card and one trope and describes the rest only as a shape. Since the repo is being deleted, a programmer working from this document alone builds a correct engine that can emit no persona, no name and no arc, and nothing in the spec tells them to copy the JSON out first. Second, three vocabularies the code enforces are cited by size but never listed: the 151-token FACTS set (the trope lint rejects the whole catalogue at load without it), the 82-token feature set, and the 19 presence situations — and the situation list exposes a substantive omission, the warlord's entire record shape including presence situation 'command', which appears nowhere in the spec. On top of that, one confident statement is inverted (deed:credited_not_actual keys on the warlord's seat, not the city it took) and contradicts the spec's own bonds section, `short_name` is documented as first-occurrence-only when it strips all, and nine of the fourteen hook `stated_purpose` strings and all sixteen `diagnostics.source_kind` phrases — both exported, player-facing fields — are absent. Fix the data-preservation gap and the three vocabularies and the rest is a good day's editing away from being implementable.

**5 blocking gap(s)** were found and are recorded in the addenda below.

## Purpose

Two reader-only packages that run last in the pipeline and turn a finished world's recorded history into a playable cast and the story arcs that cast could walk. `hero_generator` walks seven "wells" (ruins, magic, cities, guilds, countryside, ports, shrines) over the world's own records — ruined cities, wars, beast nests, ley key points, magic colleges, realm capitals, city council seats, diaspora foundings, guild halls, hamlets, fortresses, harbours, shrines and cults — and for each record builds a *candidate person* who is a named handle on an event that already happened. Each candidate rolls once against a precipitation policy; the roll is exported whether it succeeded or not, so the block records what history could have produced and did not. Survivors get a derived two-axis alignment, a weighted archetype card, one or more faces, a persona, a deterministic name and epithet, an event log, a one-sentence situation, a fame number and tier, bonds to other people, and quest hooks typed against real world objects. `story_web` then reads only the `heroes` block plus a handful of exported world facts and, for every *living* person and Dread, evaluates all 51 trope entry predicates, weights the eligible ones by a closed deterministic equation, offers the heaviest as that hero's resting hook, binds the offered trope's three acts to the hero's own names, and lists the threads each act can exit along. Neither package plans anything: the log, the situation, the hooks and the threads are the data an orchestrator improvises from. Neither ever writes to the world outside its own block, and neither imports the generator core, so a saved `world.json` replays identically to a live result.

## Where it sits in the pipeline

Both run at the very end of stage 16 of the 16-stage ladder, and again after the last age of an age-advance step, immediately before the build snapshot is captured. Call order inside `terrain_history` is fixed and load-bearing: `fill_cities` → `fill_hamlets` → `fill_castles` → `add_nomads` → `add_nomad_routes` → `add_beast_movements` → `add_encounters` → `apply_nomad_effects` → `_attach_heroes` → `_attach_story_web` → `_attach_npcs` → `_attach_key_locations` → `_attach_key_location_plans`. The comment on that ordering reads: "Bands are part of the world, so they are placed before the packages that only read it: heroes, the story web and the rosters see a world with them in."

MUST ALREADY EXIST before `hero_generator` runs (it validates the first five and raises otherwise): `config.seed` (int), `history.ages` (list), `ruins`, `settlements`, `civilizations`, `humans`, `beast_nests`. It additionally reads, optionally and defensively: `effective_config.globe_radius`, `spacing_m`, `layers` (ley_* grids), `magic.networks`, `magic.colleges`, `religion.gods`, `religion.sites`, `fisheries.ports`, `transport.routes`, `threat_assessments.cities`, `humans.cultures`, `humans.hamlets`, `humans.fortresses`, `humans.cores`, `humans.shipments`.

MUST ALREADY EXIST before `story_web` runs (it validates and raises otherwise): `config.seed` (int), `world.heroes` a dict with `status == 'ok'` carrying `people`, `dreads`, `bonds`, `realms`. It additionally reads `heroes.relics`, `heroes.camps`, `heroes.mantles`, `heroes.final_age`, `heroes.policy_revision`, and from the world: `settlements.sites`, `threat_assessments.cities`, `humans.cores`, `seasonal_food.cities`, `lunar_almanac.events`, `magic.networks`.

DEPENDS ON THEM AFTERWARDS: `npc_roster` (mirrors cast rows and shares the `hamlet-node-<n>` / `fortress-node-<n>` key space and the ten-verb quest vocabulary), `key_locations`, the time-advance `quests` lifecycle (joins `quests.quests[].quest_id` to `heroes.quest_hooks[].hook_id`), `terrain_person_state` / `terrain_read_select` (a uid→record person index spanning `heroes.people`, `heroes.dreads` and `npcs.people`, first writer winning), and the terrain lab UI. `heroes` and `story_web` are both in `STATE_KEYS`, so the stage scrubber hides them before stage 16.

ISOLATION CONTRACT. `hero_generator` imports only `world_geometry.seeds` and `heritage`; `story_web` imports neither `icarus_sim` nor `hero_generator` (it even re-declares the 82-token feature vocabulary rather than importing it). Each exposes exactly one entry point `attach(world)` which NEVER raises: any exception becomes `{'version': N, 'status': 'failed', 'error': 'TypeName: message'}` and the world still returns. Environment switches `FANTASY_WORLD_HEROES=0` and `FANTASY_WORLD_STORY_WEB=0` make `attach` return `None`, and the caller then leaves the key absent entirely (it pops any previous block first). In C++ this maps to two free functions returning an optional block, with a try/catch at the boundary — the "never crash the world" property is the whole point of the design and must be preserved.

## Inputs

=== hero_generator INPUTS ===

`config.seed` — int. The master seed. `type(...) is not int` is a hard failure (a float seed is rejected).
`history.ages` — list. Only its LENGTH is used: `final_age = len(history.ages)`. Also `ages[].wars[]` is flattened into a single war list.
`effective_config.globe_radius` — float metres, default 1.0. Used as the sphere radius for great-circle separation. ABSOLUTE METRES, post-scaling (the reference world is ~11.15 km around).
`spacing_m` — float metres per grid node, default 1000.0. Used for all grid-metre distances.

`ruins[]` (a flat list, key field `uid`; it ALSO has an `id` which is the `ruin-`-prefixed form that ley key points are built from — the two are different strings and both are used):
  `uid`, `id`, `name`, `city_class` ∈ {small, medium, capital} (default 'small'), `cause` (string: `war_<kind>`, `dragon`, `monster`, `self_magic`, or a ley-school word), `destroyed_age` (int), `civilization_id`, `population_profile`, `parent_race_id` (optional), `node` (int terrain node), `x`, `z` (grid ints), `direction` ([x,y,z] unit vector), `new_node_school` (optional string), `evidence.nest_id` (optional), `war_history[]` rows `{war_id, age, outcome ∈ {victor, defeated}, kind ∈ {civil, regional, international}, opponent_uid}`.

`settlements.sites[]` — living cities, key field `uid`, also carrying `id` (a *different* key used by colleges, hamlets, fortresses, ports and shipments to point at a city):
  `uid`, `id`, `name`, `city_class`, `civilization_id`, `population_profile`, `parent_race_id`, `node`, `x`, `z`, `direction`, `suitability` (float), `founded_age` (int), `founding_capital` (bool), `diaspora_reason` (optional ∈ {religious_schism, exile, expedition, magical_displacement}), `source_civilization_id` (optional), `war_history[]` as above.

`history.ages[].wars[]` — key field `id`: `{id, age, kind, victor_uid, victor_civilization_id, victor_parent_race_id?, defeated_uid}`.
`beast_nests.sites[]` — key field `id`: `{id, name, family, tier (int 1..5), range_m (ABSOLUTE metres), x, z, direction}`.
`civilizations.entities[]` — key field `id`: `{id, name, parent_race_id}`.
`humans.cultures[]` — key field `id`: `{id, civilization_id, city_ids[]}` (city_ids join on settlement `id`, not `uid`).
`humans.hamlets[]` — key field `id` (AN ORDINAL, unstable across ages): `{id, kind, role (e.g. 'farming', 'resource', 'coastal harbor'), core_id (city `id`), node, x, z}`.
`humans.fortresses[]` — key field `id` (ORDINAL, unstable): `{id, core_id, node, x, z, defence_score (float)}`.
`humans.cores[]` — key field `site_id` (city `id`): `{site_id, food_deficit (float)}`.
`humans.shipments[]` — `{from, to}` both city `id`s; counted per endpoint.
`magic.networks` — dict school → `{nodes: [{id, direction, intensity (float)}]}`.
`magic.colleges[]` — key field `id`: `{id, core_id (city `id`), node, x, z}`.
`layers` — dict layer name → 2-D array indexed `[z][x]`. Reads `ley_umbral`, `ley_infernal` (tainted home), and for the dominant-school scan every key starting `ley_` except `ley_holy` and `ley_primordial`.
`religion.gods[]` — key field `id`: `{id, name}`.
`religion.sites[]` — key field `id`: `{id, kind ∈ {shrine, cult}, god_id, ruin_id (a ruin `id`), node, born_under_surge (bool)}`. NOTE: carries `node` but no `x`/`z`.
`fisheries.ports[]` — key field `id`: `{id, core_id (city `id`), node, sea_node, trade_terminal (bool)}`.
`transport.routes[]` — rows with `mode == 'sea'`; endpoints read from any of `from`, `to`, `from_id`, `to_id`, `from_node`, `to_node`.
`threat_assessments.cities[]` — key field `city_uid`: `{city_uid, war_pressure (float)}`.

=== story_web INPUTS ===
`config.seed` — int (initiative stagger only).
`heroes` — the whole block above; specifically `people[]`, `dreads[]`, `bonds[]`, `realms[]`, `relics[]`, `camps[]`, `mantles[]`, `final_age`, `policy_revision`.
`settlements.sites[]` — only `id` → `uid` (a translation table; every other world read is keyed on city `uid`).
`threat_assessments.cities[]` — `{city_uid, war_pressure, wars_recent (number), enemy_living (bool), war_risk (float), war_hunger (float), regional_threat (float)}`.
`humans.cores[]` — `{site_id, food_deficit}`.
`seasonal_food.cities[]` — `{site_id, food_coverage (float, 1.0 = self-feeding)}`.
`lunar_almanac.events[]` — `{kind}`; only `surge` and `hollow_night` matter, and a single occurrence anywhere counts for every hero.
`magic.networks.<school>.nodes[]` — `{id, intensity}`.
Every one of these reads skips a malformed row rather than failing: the docstring says "a bad row costs one fact".

`summary` = {living, legends, dreads, realms, orgs, camps, hooks, candidates, precipitated} — all ints; `living`/`legends` count `people` by `status`.

`people[]` — key field `uid` (string, shape `hero-<role>-<anchor>`; see the uid table in ALGORITHM). Fields:
  uid, role ∈ {pretender, warlord, magister, domain_holder, sovereign, council, champion, prophet, heresiarch, exile, founder, reeve, castellan, harbourmaster, keeper}; well ∈ {ruins, magic, cities, guilds, hamlets, fortresses, ports, shrines}; status ∈ {living, legend}; civilization_id; race_id (PARENT race, selects a language family only); born_age (int ≥ 1 except ruin-born which use destroyed_age); home (null or {kind:'city', uid, name}); presence (null or {site_kind ∈ {city, ruin, camp, college, nest, hamlet, fortress, port, shrine}, uid, situation}); realm_uid (nullable); deeds[]; claim {verb, target_uid, target_name}; fame (float, 3 dp); tier ∈ {notable, renowned, legendary} — THIS IS A FAME BAND, NOT A DANGER RATING; name; epithet; display_name = "name epithet"; archetype (card id); archetype_name; alignment {law, good (floats −1..1, 3 dp), label, code (2 chars), drift (null or {law, good})}; persona {...}; faces[] {label, name, apparent_role, alignment, claim, persona}; log[] {age, event_kind, event_id, role, text}; situation (one sentence, may be ''); companion {eligible (bool), join_condition (null|rescued|found|hired), offered_from_face (nullable)}; rivals[] (sorted uids), kin[], allies[]; org_uid (ALWAYS null — see OPEN QUESTIONS); seed (uint32, a per-person sub-seed handed to consumers); selectable[] (the sorted feature tokens that were true); and the always-present-but-often-null set {predecessor_uid, school, node_id, seat, nest_id, site_name}.

## Algorithm

################################################################
## PART A — hero_generator.generate(world, policies=None)
################################################################

A0. VALIDATE. `world` must be a dict; `type(world['config']['seed']) is int` exactly (bool and float are rejected); `world['history']['ages']` must be a list; the keys `ruins`, `settlements`, `civilizations`, `humans`, `beast_nests` must all be present. Otherwise raise ValueError, which `attach` converts to a failed block.

A1. LOAD POLICIES. Five JSON documents: archetypes, axis_overlays, alignment, names, wells. Parsing rules that are part of the contract: duplicate object keys are a hard error; the JSON constants `NaN`, `Infinity`, `-Infinity` are a hard error; every document must carry an integer `revision` ≥ 1. Then lint archetypes (each card's key set must be EXACTLY {id,name,prior,requires,boosts,drift,intensity,faces,core,pole_notes,lines}; ids unique; `core` key set exactly {belief,wants,fears,tells,mechanic,never} with all but `never` non-empty; `pole_notes` exactly the four poles, all non-empty; `lines` non-empty with every key exactly 2 characters; `requires` non-empty, every conjunction a non-empty list; `prior` exactly {law,good}; `intensity` ∈ {null,'corner','good_axis'}; `faces` ∈ {null, ['public','true'], ['calm','unleashed'], ['first','second']}) and lint overlays (each of law/{lawful,neutral,chaotic} and good/{good,neutral,evil} must have exactly {voice,lies,never,cornered,toward_player} with `never` a list).

A2. `seed = world.config.seed`. `radius = effective_config.globe_radius or 1.0`. `final_age = len(history.ages)`.

A3. BUILD REALMS (realms.build_realms). For each culture in `humans.cultures`, IN LIST ORDER:
    members = [cities_by_id[i] for i in culture.city_ids if present]   # join is settlement `id`
    if members empty: skip the culture entirely.
    capital = first member with city_class == 'capital'; if none, `max(members, key=(suitability, -node))` — note the NEGATED node, so on a suitability tie the LOWEST node number wins, and `max` on a tie of the whole key returns the FIRST such member.
    Emit {uid: 'realm-'+culture.id, name: heritage realm name (see A3a), english_name: "Realm of " + short(capital.name), civilization_id, civilization_name (from civilizations, falling back to the id), parent_race_id: capital.parent_race_id or civilization.parent_race_id, capital_uid, city_uids: [member uids in culture order], culture_id, sovereign_uid: null}.
    A3a. Realm name = `heritage.realm_name(resolve(culture.civilization_id, capital.parent_race_id or 'human'), short(capital.name))`, falling back to "Realm of <short capital name>" when the tongue has no realm morpheme. `short(name)` strips the first occurrence of the literal substring " City" (a dead-reader compatibility strip: the live name generator no longer emits it, but fixtures do — keep the strip, it is the identity on real worlds).
    `realm_by_city` = flat map city uid → realm, built by iterating realms in order then their city_uids; a city in two cultures resolves to the LAST realm written.

A4. RUN THE WELLS, IN THIS EXACT ORDER, accumulating `people`, `dreads`, `rolls`, `orgs`:
    1. ruins well → (people, dreads, rolls)
    2. magic well → (people, rolls) appended
    3. cities well → (people, rolls, orgs)
    4. guilds well → (people, rolls, orgs) — takes the globe radius as an extra argument
    5. people += city_people + guild_people; rolls += city_rolls + guild_rolls; orgs += guild_orgs
    6. countryside well, then ports well, then shrines well, each → (people, rolls) appended
    (The order matters only for the order of `rolls[]` and for the pre-sort order of `people`; the roll VALUES are order-independent because each candidate opens its own named RNG stream.)

A5. THE SHARED ROLL. Every well precipitates through one helper:
    chance(policy, value) = round(clamp(value, 0.0, policy.cap), 3)           # cap = 0.95
    roll(record, kind, chance, seed, rolls, event_id=None, age=None):
        draw = Rng::child(seed, "hero-roll-" + record.uid).random()          # one draw, [0,1)
        precipitated = draw < chance
        first = record.deeds[0] if record has a non-empty `deeds` else {}
        append to rolls: {candidate_uid: record.uid, kind, event_id: event_id or first.event_id,
                          age: age if age is not None else first.age, chance, roll: round(draw,6), precipitated}
        return precipitated
    A fresh named stream per candidate is what makes the ledger replay-stable regardless of how many candidates precede it.

A6. WELL 1 — RUINS (`wells/ruins.py`). Precompute: living cities by uid; nests by id; `wars_by_defeated` = {war.defeated_uid → war} over every war in every age (LAST war for a uid wins); `lost_per_civilization` = count of ruins per civilization_id.
    Iterate `ruins` IN EXPORT ORDER. For each ruin:
      (a) Always build a PRETENDER candidate (the heir):
          same = living cities whose `population_profile` equals the ruin's
          home = nearest_city(ruin, same, radius)        # see A6a
          alive = home is not None AND (final_age − destroyed_age) ≤ 1
          war_deeds = for each row of ruin.war_history: {event_kind:'war', event_id: war_id, age, role: 'credited' if outcome=='victor' else 'victim', kind, opponent_uid}
          features = {'role:pretender', 'home:fell', 'stake:lost', 'heir:'+city_class}
                     + 'sides:both' if the war_deeds contain BOTH 'credited' and 'victim'
                     + 'civ:lost_many' if lost_per_civilization[civ] ≥ 2
                     + 'dread:living' if cause ∈ {dragon, monster} AND evidence.nest_id names a still-placed nest
          uid = 'hero-pretender-' + ruin.uid; status = living if alive else legend;
          home ref = {kind:'city', uid, name} when alive else null;
          presence = {site_kind:'city', uid: home.uid, situation:'court'} when alive else null;
          realm_uid = realm_by_city[home.uid].uid when alive else null;
          lost = {uid, ruin_id: ruin.id, name, city_class, cause, destroyed_age};
          deeds = [{event_kind:'ruin', event_id: ruin.id, age, role:'heir'}] + war_deeds;
          claim = {verb:'retake', target_uid: ruin.uid, target_name: ruin.name};
          born_age = destroyed_age; race_id = parent_race(world, ruin).
      (b) If a war names this ruin as its defeated city, fold it into a WARLORD keyed `f"{war.age}-{war.victor_uid}"` (so one person per victor city per age). On first sight build:
          home = living city with uid == war.victor_uid (may be absent — the victor itself later fell)
          alive = home is not None AND (final_age − war.age) ≤ 1
          features = {'role:warlord', 'war:'+war.kind+'_victor'}
                     + 'home:fell_later' if home is None
                     + 'realm:contested' if home exists and ANY city of home's realm has a war_history row whose opponent_uid is a LIVING city (fall back to [home] alone when the city is in no realm)
                     + 'civ:lost_many' if lost_per_civilization[war.victor_civilization_id] ≥ 2
                     + 'sides:both' if home's own war_history contains both 'victor' and 'defeated'
          victor_name = home.name if home else the name of the ruin whose uid == victor_uid (linear scan over ruins) else the uid itself
          uid = 'hero-warlord-' + key; claim = {verb:'hold', target_uid: victor_uid, target_name: victor_name};
          race_id = war.victor_parent_race_id or parent_race(world, home or ruin); born_age = war.age.
          Then ALWAYS append to that warlord: a deed {event_kind:'war', event_id: war.id, age, role:'credited', kind, defeated_uid, defeated_name, defeated_class} and a `defeated` row {uid, name, war_id, kind}.
      (c) If cause ∈ {dragon, monster} and `evidence.nest_id` is set, fold into a DREAD keyed on the nest id (`dread-<nest id>`), created on first sight with species = nest.name (or, when the nest is gone, derived from the id: split `nest-abyssal-choir-worms-156` on '-', drop the leading 'nest' and the trailing ordinal, join with spaces, capitalise the first letter → "Abyssal choir worms"), family = nest.family or null, nest_tier = nest.tier or 5, status living iff the nest is still placed, presence {site_kind:'nest', uid: nest_id, situation:'lair'} when living, features {'role:dread'}. Then append a deed {event_kind:'ruin', event_id: ruin.id, age, role:'actual', cause, city_name, city_class} and a `destroyed` row. After each append: add 'dread:long_lived' if family ∈ {draconic, undead, aberrant}; add 'dread:ages_2' if the deeds span ≥ 2 distinct ages.
    THEN roll, in this order:
      heirs in ruin order, chance = clamp(0.4 + per_city_class[class]) where per_city_class = {small 0.0, medium 0.2, capital 0.4}.
      warlords: if `one_per_city` (it is true), first REDUCE to one warlord per victor city — keep the key with the greatest `(born_age, key)` tuple per victor_uid — then iterate the surviving keys in SORTED KEY ORDER and roll each with chance = clamp(0.25 + max over the person's war kinds of {civil 0.1, regional 0.25, international 0.4} + 0.15 × (number of wars − 1)). The comment on the reduction: "A city remembers one warlord: the most recent victor. Earlier victors' wars stay in the city's history and the survivor's deeds; they do not each precipitate a person."
      dreads: iterate nest ids in SORTED ORDER, chance = clamp(0.5 + 0.08 × nest_tier).
    A6a. nearest_city(target, candidates, radius): minimise the tuple `(separation(target, city, radius), city.uid)`, where separation(a,b,R) = R · acos(clamp(dot(a.direction, b.direction), −1, 1)) — great-circle surface metres. The uid tie-break is explicit so the answer never depends on list order. Returns null on an empty candidate list.

A10. WELL 5 — COUNTRYSIDE (`wells/countryside.py`). Distances here are GRID metres: hypot(Δx, Δz) × spacing_m, never great-circle, because hamlets and fortresses carry no globe direction. The same measure is reused by the quest-difficulty pressure term so the two passes cannot disagree.
    THE ANCHOR (the single most important id decision in the package): `anchor(site, kind) = f"{kind}-node-{site.node}"` when the site has a node, else the site's ordinal id as a string. The docstring is worth carrying verbatim in spirit: `humans.hamlets[].id` and `humans.fortresses[].id` are ORDINALS — the position in an accepted list that `terrain_humans` rebuilds every age, fortresses being accepted in descending `defence_score` over a strategic map rebuilt from the road graph — so membership AND ordering change at every age boundary; `fortress-36` names different ground after an advance and the old uid still resolves, to a real person at a real fortress, the wrong one, with no error. The terrain node does not renumber. `-node-` is spelled into the key because `fortress-13` and `fortress-node-13` would otherwise read alike and mean different things. The kind is part of the key because a hamlet and a fortress can share a node: measured 0 of 56 shared on the seed-42 size-33 sample but 18 shared on the size-65 sample, so the prefix is load-bearing at other sizes even where it looks redundant. The anchor is spent in FOUR places for one person — `uid`, `presence.uid`, `claim.target_uid`, `deeds[].event_id` — and the comment says "Repairing one leaves three ways to join the wrong row, and three of them are the ones a story layer, a quest and a save file reach for."
    (a) For each hamlet in order: skip unless its `core_id` names a living city AND `kind == 'hamlet'` AND `'harbor'` is NOT a substring of `role` AND the string form of its `id` does not start with 'coastal' (those belong to the ports well). nearest dangerous nest by grid metres (skipping nests without x/z, tie on nest id); `threatened` = nest exists AND distance ≤ 1.5 × (nest.range_m or 1000). Build a REEVE — uid 'hero-reeve-'+anchor, born_age = max(1, final_age), status living, home = the core city, site_name = "the <word> below <short city name>" where word = {farming→farmstead, resource→quarry camp, coastal→fishing village, otherwise hamlet} keyed on the FIRST SPACE-SEPARATED TOKEN of `role`, presence {site_kind:'hamlet', uid: anchor, situation:'reeve'}, nest_id/nest_name when threatened, deeds [{event_kind:'hamlet', event_id: anchor, age: final_age, role:'keeper'}], claim {verb:'protect', target_uid: anchor, target_name: site_name}, features {'role:reeve', 'hamlet:'+first token of role or 'farming'} + 'hamlet:starving' when the core's `food_deficit` > 0 + 'hamlet:threatened' when threatened. Roll chance = clamp(0.25 + 0.25 if starving + 0.3 if threatened).
    (b) For each fortress in order: skip unless `core_id` names a living city. `pressed` = the core city's threat assessment `war_pressure` > 0. Build a CASTELLAN — uid 'hero-castellan-'+anchor, site_name = "the fortress above <short city name>", presence {site_kind:'fortress', uid: anchor, situation:'garrison'}, deeds/claim keyed on the anchor with verb 'hold', features {'role:castellan','order:member','warden:post'} + 'fortress:pressed'. Roll chance = clamp(0.35 + 0.3 if pressed + 0.05 × defence_score).

A14. PLACEMENT (`sites.place`). For each person in current list order: SKIP when `final_age − born_age > 1` OR the person already has a `home`. Otherwise let `camp` = the camp (if any) standing in the person's own `lost` ruin.

A15. SORT THE CAST: `people.sort(key=(born_age, uid))`. EVERYTHING downstream depends on this order.

A16. FAME, PER PERSON, in that order:
    magnitude = Σ over deeds:
        ruin+heir              → class_weight(person.lost.city_class)
        ruin+actual            → 1.0 × class_weight(person.lost.city_class)
        ruin+keeper or credited→ 0.5 × class_weight(person.lost.city_class)
        war+credited           → war_weight(kind) × class_weight(deed.defeated_class or 'small')
        war+anything else      → 0.5 × war_weight(kind)
        nest                   → 0.6 × (deed.tier or 1)
        founding               → 1.5
        hamlet/shrine          → 0.5 ; fortress/port → 1.0
      where class_weight = {small 1, medium 2, capital 3} (unknown → 1) and war_weight = {civil 1, regional 2, international 3} (unknown → 1).
      then: a SOVEREIGN adds class_weight(home.city_class or 'capital'); a COUNCIL member adds seat_weight = {magistrate 1.5, commander 1.5, market_steward 1.2, chaplain 1.0, mage 1.0, librarian 0.8} (unknown seat → 1.0).
    reach = 0.5 (LEGEND_REACH) when the person has no home; otherwise class_weight(home city's class, default small) + 0.25 × (number of cities in their realm, or 1 when they have no realm).
    fame = round(magnitude × (1 + reach), 3). tier = 'legendary' if fame ≥ 24, else 'renowned' if ≥ 8, else 'notable'. (Calibration comment: "A capital heir with a capital seat lands near 19; a victor who took a capital in an international war near 38. Legendary is reserved for the latter kind of deed.")
    Then add features: 'fame:renowned' when tier is renowned or legendary; 'fame:legendary' when legendary.
    Then compute `anchor_direction` — a temporary field, the globe direction of the place the person stands, used only for the opposing-ley-node search: try presence.site_kind ∈ {city, ruin, camp} looked up by presence.uid; else the `lost` ruin; else the `home` city; else null.

A17. PREDECESSORS (`_predecessors`). legends = people with status 'legend' and claim verb 'retake'. For each LIVING person, earlier = legends of the SAME civilization_id with a strictly smaller born_age; if any, add feature 'legend:predecessor' and set `predecessor_uid` = `min(earlier, key=(-fame, uid))` — i.e. the most famous, uid-tie-broken.

A18. CROSS-CUTTING FEATURES (`features.apply`), computed once the whole cast is known:
    - 'ley:tainted_home': the home city's `layers['ley_umbral'][z][x]` or `layers['ley_infernal'][z][x]` exceeds `features.tainted_threshold` (0.45). Any lookup failure is swallowed.
    - 'deeds:two_civilizations': the set of civilizations of the cities/ruins named by the person's deeds' `opponent_uid`, minus null, has size ≥ 2.
    - 'villain:prior_age' AND 'stake:regained' together: the person is a PRETENDER, born_age < final_age, and their civilization founded a city STRICTLY LATER than their birth. Carry the disclaimer: this token has NOTHING to do with the world model's super-villain field (a continuous tier, a reach in metres, a seat and held ley nodes, at most one per cultural region, in the `villains` block). It carries no tier, no reach, no region and no seat; a world can be full of them with an empty `villains` block; filtering for it to find "people connected to a super villain" returns dispossessed claimants with no error; and it is NOT evidence a super villain stood here in a prior age, which `villains.fallen` answers and this does not.
    - 'rival:spared': the person is seated (role ∈ {sovereign, warlord}) and their civilization has a living camp leader.
    - 'deed:credited_not_actual': the person is a champion whose home city is a city some warlord is credited with taking.
    - 'seat:none': role ∉ {sovereign, council, warlord} and status is living.
    - 'heir:unclaimed': has 'legend:predecessor' and is a pretender.
    - 'council:outranks_sovereign' / 'sovereign:advised': group the LIVING people by realm_uid (dict insertion order); in each realm with a sovereign, any council member whose fame strictly exceeds the sovereign's gains the first token and the sovereign gains the second.
    - 'mentor:successor': a LIVING person of tier renowned or legendary who has any other living compatriot born strictly later.
A19. FINISH THE SEATED FIRST. `seated` = people with role ∈ {sovereign, warlord}, in cast order; run `_finish_person` on each. Then `mark_rebels`: tyrant civilizations = the civilizations of seated people whose chosen archetype is 'tyrant'; every person who has NOT yet been finished (archetype still absent), whose civilization is a tyrant civilization, and who carries 'seat:none', gains 'realm:tyrant'. Then run `_finish_person` on every remaining unfinished person, in cast order. This two-pass structure exists so a Tyrant can make Rebels; a Rebel card requires 'realm:tyrant' ∧ 'seat:none'.

A20. `_finish_person(person)`:
    draw = Rng::child(seed, "hero-archetype-" + uid)          # ONE stream, used by choose() and then by intensify()
    alignment = derive_person(person) — see A21
    card = choose(cards, features, alignment, draw) — see A22. A NULL CARD IS A HARD ERROR for a person: raise, which fails the whole block.
    alignment = intensify(alignment, card.intensity, draw); alignment.drift = card.drift
    (name, epithet) = person_name(...) — see A23 — using its own stream "hero-name-" + uid
    faces = build_faces(...) — see A24 — using its own stream "hero-face-" + uid where needed
    top-level `persona` = the persona of the first face whose label is NOT in {public, unleashed, second}, unless there is only one face, in which case the single face's persona. (So: one face → that one; public/true → the `true` persona; calm/unleashed → `calm`; first/second → `first`.)
    `log` = person_log; `situation` = person_situation (A26, A27)
    `companion` = {eligible: status is living AND presence.situation ∈ {captive, hidden, refugee}; join_condition: {captive→rescued, hidden→found, refugee→hired} when living else null; offered_from_face: faces[0].label when the situation qualifies else null}
    `org_uid` = null (always); `seed` = Rng::child(seed, "hero-seed-" + uid).getrandbits(32)
    default the six optional keys {predecessor_uid, school, node_id, seat, nest_id, site_name} to null if absent
    `selectable` = the sorted feature list; the mutable feature SET is then removed from the record.

A21. ALIGNMENT (`alignment.derive_person`). Start from `civilization_bias[civilization_id]` (default {0,0}). For each deed: a `ruin`+`heir` deed contributes shift key 'ruin_heir_capital' when the lost city was a capital else 'ruin_heir'; a `war` deed contributes `war_<kind (default civil)>_<'victor' if role=='credited' else 'defeated'>`; every other deed is skipped. Add the shift's law and good to the running value AND to a separate `decided_law`/`decided_good` accumulator. Then draw ONE stream "hero-alignment-"+uid and take TWO uniform(−jitter, +jitter) draws, law first then good, with jitter = 0.35. law = bounded(clamp(law + jitter1), decided_law); good = bounded(clamp(good + jitter2), decided_good), where bounded(v, d) = max(0.01, v) when d > 0, min(−0.01, v) when d < 0, and v otherwise — "Jitter may move a value but never across zero once a deed put it on one side." Then `record(law, good)`: round each to 3 dp after clamping to ±1; pole(v) = +1 when v > 0.34, −1 when v < −0.34, else 0; label = "<Chaotic|Neutral|Lawful> <Evil|Neutral|Good>", with the pair (Neutral, Neutral) rendering as the single string "True Neutral"; code = "CNL"[pole(law)+1] + "ENG"[pole(good)+1].
    A DREAD's alignment instead = clamp(dread_base + dread_family[family] + jitter) on each axis, with dread_base = {law −0.4, good −0.7} and the family table {draconic +0.6/+0.1, undead +0.3/−0.2, infernal +0.2/−0.25, aberrant −0.5/0, fantastic 0/+0.3, primordial 0/+0.4, holy +0.5/+0.9}; no deed shifts, no sign-locking.
    INTENSIFY(alignment, intensity, draw): null → unchanged. Otherwise sign(v) = +1 when v > 0, −1 when v < 0, and when v is EXACTLY 0 one `draw.random() < 0.5` decides (+1/−1) — note the good axis is evaluated first, then the law axis, so the draw order is good-then-law when both are zero. `good_axis` sets good to ±1 and leaves law; `corner` sets both to ±1. Re-record (round, relabel) preserving the existing drift.

A22. ARCHETYPE CHOICE (`archetypes.choose`). A card is ELIGIBLE when ANY one of its `requires` conjunctions is entirely a subset of the person's feature set (plain membership; no negation here — negation exists only in story_web). weight(card) = Π over `boosts` entries whose fact the person carries, of the factor, times `max(0.25, 1 + 0.75 × (prior.law × alignment.law + prior.good × alignment.good))` — the 0.75 gain and the 0.25 floor are HARDCODED IN CODE, not policy. Eligible cards are collected IN CATALOGUE ORDER; if none, return null. total = Σ weights; if total ≤ 0 return null (unreachable in practice, all factors being positive). selector = draw.random() × total; walk the options in order subtracting each weight and return the first card at which selector ≤ 0; fall back to the last option. "Nothing is clamped by alignment: a prior only changes frequency."

A23. NAMES (`naming.person_name`). One stream "hero-name-"+uid, used FIRST by the heritage name generator and THEN by the epithet choice, so the two are coupled — the number of draws heritage takes shifts the epithet. Given name = `heritage.person_name(heritage.resolve(civilization_id, race_id or 'human'), heritage.lexicon(), draw)`. A record with no `civilization_id` RAISES rather than falling back: "The silent fallback this replaces is the defect — it gave four peoples human names for as long as they have existed, and a loud failure is the only way that does not happen again." (Keyed on the parent race, a desert human and a cold human drew from one table and tidekin, gnome, hill_dwarf and frosthold_dwarf silently fell through to the human one.)
    Epithet: context = {lost: short(lost.name) or '', home: short(home.name) or '', victor: short(victor_name) or '', defeated: short(defeated[0].name) or '', school: school or 'weave', site: site_name with the first 'the ' removed, seat: {magistrate→Magistrate, commander→Commander, chaplain→Chaplain, market_steward→Steward, mage→Court Mage, librarian→Archivist} defaulting to 'Councillor'}. candidates = `names.epithets[role]`, plus `names.epithets['legend']` appended when the person is a legend. usable = those whose every placeholder has a non-empty context value, falling back to the whole list when that filters everything out. epithet = fill(draw.choice(usable), context). `display_name` = "<name> <epithet>".
    FILL: for each context key, replace `{key}` with the value AND `{Key}` (first letter upper-cased, rest untouched) with the value's first letter upper-cased and the rest untouched. Two things the comments pin: only the first letter is raised because `str.capitalize` would lower the rest and turn `Court Mage` into `Court mage`; and the placeholder scan case-folds (`{School}` finds `school`) because without the fold a capitalised token resolves to nothing, the template is judged unusable and is silently dropped from the draw — "the epithet would not render wrong, it would never be chosen."
    A DREAD's epithet uses the same stream name, context {city: short(destroyed[0].name), species}, and `names.epithets['dread']`; its `name` IS the epithet and `display_name` = "<species>, <epithet>".

A24. FACES (`faces.build`). The base face is {label:'public', name, apparent_role: role, alignment, claim, persona: compose(card, overlays, alignment)}.
    `faces: null` → exactly [base].
    `['public','true']` → stream "hero-face-"+uid. shown = record(alignment.law, max(0.5, |alignment.good|)) — "the mask is always visibly good". cover = draw.choice(names.cover_roles[role] or cover_roles['default']). Public face = {label:'public', name, apparent_role: cover, alignment: shown, claim {verb:'protect', same target}, persona: compose(card, overlays, shown)}. True face = base relabelled 'true'. Order: [public, true].
    `['calm','unleashed']` → loosed = record(−1.0, min(alignment.good, −0.5)); [base as 'calm', base as 'unleashed' with the loosed alignment and its own persona]. NO draw.
    `['first','second']` → stream "hero-face-"+uid; other = record(−law + uniform(−0.3, 0.3), −good + uniform(−0.3, 0.3)) with the LAW draw taken first; [base as 'first', base as 'second' with `other`].

A25. PERSONA (`persona.compose`) = core(card) + overlay(law pole) + overlay(good pole) + pole notes:
    {archetype: card.id, belief, wants, fears, tells, mechanic (all copied from the card's core),
     manner: the card's pole_notes for each of (law pole, good pole) that is not 'neutral', joined with a single space, in that order; when both are neutral the literal sentence "Neither law nor morality pulls harder than the other; the archetype shows almost unmodified.",
     voice: law.voice + " " + good.voice,
     lies:  good.lies  + " " + law.lies,          ← note the reversed order
     toward_player: good.toward_player + " " + law.toward_player,   ← reversed
     cornered: law.cornered + " " + good.cornered,
     never: the card's core.never list, then every entry of law.never followed by good.never that is not already present (order-preserving de-duplication) — so a downstream proposal that crosses a hard line can be rejected mechanically,
     line: the card's sample utterance for the person's 2-char alignment code; when that exact code is absent, the first line (in catalogue/dict insertion order) whose SECOND character matches (same good pole); failing that, the first line at all.}

A26. EVENT LOG (`facts.person_log`). One entry per deed the person's role knows how to narrate; entries are {age, event_kind, event_id, role, text} and are SORTED at the end by (age, event_id). The branch chain, in order, is: hamlet deed → "Speaks for <site>, which feeds <home>" plus "; the <lowercased nest name> hunts its fields" when threatened; fortress → "Commands <site>, on the road to <home>."; port → "Runs <site>; every hull bound for <home> pays its due."; shrine → "<Leads|Tends> <site>." (Leads for a heresiarch); then role-keyed: pretender+ruin → "<lost>, <small city|city|capital> of the <civilization name>, was destroyed by <cause phrase>; its heir survived."; pretender+victim → "Lost the <kind> war that ended <lost>."; pretender otherwise → "<lost> won a <kind> war."; warlord → "Led <victor> to victory over <defeated> in a <kind> war; <defeated> is a ruin."; magister → "<lost> destroyed itself in a magical experiment; the master of its college walked out of the ash, and a <school> key point burns where the city stood."; domain_holder → "Took up the <school> key point left where <lost> fell to <cause phrase>."; sovereign → "<home> <won|lost> a <kind> war."; champion+nest → "Holds the line for <home> against the <lowercased nest name>."; champion otherwise → "Stood for <lost> against the <lowercased nest name>, and the city fell anyway."; prophet/heresiarch/exile/founder → "Led the <reason with underscores as spaces> that founded <target name for exile/founder, else 'a new city'>.". CAUSE PHRASE: a cause starting 'war_' reads "the <rest> war"; dragon → "a dragon"; monster → "a monster"; self_magic → "its own magic"; anything else → "<a|an> <cause> leyline surge" with the article chosen on the first letter being a vowel. A DREAD's log is one entry per kill, "Destroyed <city name>.", sorted by (age, event_id).

A27. SITUATION (`facts.person_situation`) — one sentence, dispatched on role and presence.site_kind, with '' as the final fallback. The full table: reeve → "Reeve of <site>; <the granary is short|the harvest is in>" plus ", and the <nest> is close." or "."; castellan → "Holds <site> for <home>."; harbourmaster → "Keeps the ledger of <site>."; keeper → "Tends <site>" + " and shelters at <home>." or "; no city of the old people stands near."; heresiarch at a shrine → "Preaches from <site>" + " toward <target>." when converting else "."; pretender → at a camp "Leads <camp name>; still claims <lost>.", with a home "Sheltered at <home>; still claims <lost>.", else "No city of the <civilization> survives to shelter the heir; the claim on <lost> passed into legend."; warlord → "<victor> itself fell in a later age; the victor is remembered, not seated." when victor_fell, else "Holds <victor>."; magister → camp: "Held captive at <camp>." or "Hiding at <camp>, unrecognised."; city: "A refugee at <home>; the college is ash, the <school> key point is not."; college: "Heads the college near <short home>."; else "Gone; the last master of <lost> is a name in the ash."; domain_holder → ruin: "Wards the <school> key point in the ruins of <short lost>." else "The <school> key point at <short lost> has no keeper now."; sovereign → "Sits the throne of <realm name> at <home>."; council → "Holds the <seat with underscores as spaces> seat at <home>."; champion → city / camp / refugee / nameless variants naming the Order; prophet & heresiarch → "Preaches at <home>." or "The schism outlived its prophet."; exile & founder → "Leads <home>." or "The founding outlived its leader.". A DREAD: "The lair still stands; the <species> has not been driven out." when living, else "The lair is gone, but the name of the <species> is not."

A28. FINISH THE DREADS, in the order the ruins well produced them (sorted nest id). fame: magnitude = Σ over deeds of 0.6 × nest_tier × class_weight(deed.city_class or 'small'); reach = min(3.0, nest.range_m / 1000) when the nest still exists (RANGE_M IS ABSOLUTE METRES, so this is "reach in kilometres, capped at 3") else 0.5. Then `_finish_dread`: same archetype stream and choice, but A NULL CARD IS TOLERATED (archetype, archetype_name and persona are simply null and the alignment is not intensified).

A29. RELICS (`sites.relics`) — no roll, one per ruin, in ruin order. kind and name template by CAUSE KIND (a cause starting 'war_' → 'war'; dragon/monster → 'beast'; self_magic → 'self_magic'; anything else → 'ley'): self_magic and ley → ('focus', "the {school} focus of {name}"); war → ('banner', "the banner of {name}"); beast → ('reliquary', "the reliquary of {name}"); AND a capital whose relic would be a banner is promoted to ('crown', "the crown of {name}"). `school` is `ruin.new_node_school` for a focus (default 'weave' in the rendered name) and null otherwise. `resting_at` = ruin uid; `holder_uid` always null.

A30. QUEST HOOKS (`hooks.quest_hooks`) — for each LIVING person in cast order.
    covert = the person has more than one face AND faces[0].label == 'public'; `offered_from_face` = 'public' when covert else faces[0].label.
    The hook branch is a first-match chain on the claim and the role, and the ORDER IS LOAD-BEARING:
      claim.verb == 'retake' → "Help me take back <target name>." with effect {kind:'ruin', uid, action:'reclaim'}; PLUS, when a relic rests in that ruin, "Recover <relic name> from the ruins." with {kind:'relic', uid: relic.uid, action:'recover'}.
      claim.verb == 'hold' AND role == 'warlord' → "Stand with <target> when they come for it." / {kind:'city', uid, action:'defend'}.
      person has a non-null `node_id` AND claim.verb ∈ {hold, exploit} → the LEY PAIR: own = {kind:'ley_node', node_id, school, intensity_delta: +0.5}; honest text "Strengthen <node name>."; cover text "Restore the old shrine at <short lost name or claim target>; the land around it is sick."; emit the cover text when covert (and set `unwitting`). Then find the NEAREST OPPOSING NODE: opposite = `magic.opposites[school]` ({radiant↔umbral, fire↔water, earth↔air, weave↔infernal}); if that network exists and the person has an `anchor_direction`, minimise (angular separation from the anchor with radius 1.0, node id) over its nodes; emit a second hook {kind:'ley_node', node_id: that node, school: opposite, intensity_delta: −0.5} with honest text "Weaken <node name>; it chokes the <school>." or cover text "Cleanse <node name>; something there is poisoning the valley."
      role == 'reeve' → "See <target> through the season." / {kind:'hamlet', uid, action:'defend'}; plus, when threatened, "Drive the <lowercased nest name> from our fields." / {kind:'nest', nest_id, action:'slay'}.
      role == 'castellan' → {kind:'fortress', action:'defend'}. role == 'harbourmaster' → {kind:'port', action:'trade'}. role == 'keeper' → {kind:'shrine', action:'tend'}. role == 'sovereign' → {kind:'city', uid: home.uid, action:'defend'}. role == 'council' with seat market_steward → {kind:'city', action:'trade'}; with seat commander → {kind:'city', action:'defend'} (other seats emit NOTHING). role == 'champion' with a nest_id → {kind:'nest', nest_id, action:'slay'}. role ∈ {heresiarch, prophet} with claim 'convert' → {kind:'city', uid: claim target, action:'convert'}. role ∈ {exile, founder, prophet} → {kind:'city', action:'defend'}. role == 'magister' with a `college` → {kind:'college', uid: college.id, action:'supply'}.
    NODE NAME: a node id ending '-key' whose prefix (id minus the last 4 characters) is a real ruin renders "the <school> key point at <short ruin name>"; otherwise "the <school> node <id>".
    For each produced (text, effect, unwitting) pair, index_of starting at 0:
      resolve the TARGET (A30a), compute the VERB (A30b) — a verb outside the ten-word vocabulary is a HARD ERROR — and the DIFFICULTY (A30c), and emit {hook_id: "hook-<giver uid>-<index>", giver_uid, offered_from_face, stated_purpose, actual_effect, unwitting, target: effect.uid or effect.node_id or effect.nest_id (in that order — reading only uid or node_id left every slay hook pointing at nothing), verb, difficulty, target_node, unsited_reason}.
    A30a. `_target(effect)` → (record, node, unsited_reason). For a ley_node: only a `-key` id whose ruin exists resolves — return that ruin and its node; every other ley node returns (null, null, 'ley_node_has_no_site'), because a bare node is "a direction and an intensity with no footprint anywhere in the world" and is reported rather than given an invented position. For a relic: look up the ruin the relic rests in. For a ruin: by `uid`. For a nest: by `nest_id` falling back to `uid`. For everything else: the kind's own index by `uid` — cities by `uid`, ports/shrines/colleges by `id`, hamlets and fortresses by BOTH their ordinal id AND their `<kind>-node-<n>` anchor (the ordinal is written first and the anchor second, so a collision resolves to the anchor, "the one that survives an age"). A missing record → (null, null, 'target_not_found'). A record with no `node` → (record, null, 'target_has_no_node'). A shrine record has a node but no x/z, so its RUIN is returned as the measuring record while the SHRINE's node is returned as the position.
    A30b. VERB = the effect's own `action` when it has one; a ley effect has none, so its verb is the sign of the delta: ≥ 0 → 'tend', < 0 → 'cleanse'. The closed ten-word vocabulary is (reclaim, recover, defend, slay, trade, tend, convert, supply, cleanse, investigate) — identical to the roster's post verbs; it is code and not policy because "a new verb needs a new hook branch to emit it".
    A30c. DIFFICULTY = clamp(1, 5, floor(opposition + pressure + 0.5)).
        opposition: a nest answers with its own `tier`; a ley node with `ley_floor (1.0) + ley_intensity_weight (0.5) × intensity`; everything else takes a floor from the policy table {ruin 2, relic 2, city 2, hamlet 2, fortress 2, port 2, shrine 1, college 1}, defaulting to `difficulty_min`.
        pressure: 0 for a nest target (PRESSURE_EXEMPT — its tier is already the whole answer and its own range_m would otherwise count twice) and 0 when the measuring record has no x/z; otherwise min(pressure_cap 1.0, pressure_per_tier 0.25 × the HIGHEST tier among the nests whose own `range_m` reaches the record in GRID metres). "Nothing reaching it is 0.0, which is a statement about the ground rather than a missing value: quiet country is the common case and it should read as quiet."
        The banding is explicitly floor(x + 0.5) and NOT round(), "because CPython rounds halves to even and a rubric that sends 2.5 down and 3.5 up reads as arbitrary to anyone checking it by hand."
        Rubric meaning: 1 harmless, 2 can hurt you, 3 kills the careless, 4 kills the prepared, 5 a campaign threat. Only opposition can reach 5 on its own, so "a long walk past a lair can never turn an errand into a campaign threat."

A31. TIDY. Delete the temporary `anchor_direction` and `dispossessed` fields from every person. Compute BONDS (A32). For each person, derive `rivals` (sorted unique partners across edges of kind rival or betrayed), `kin` (kind kin), `allies` (kinds ally or mentor) — all sorted uid lists. Drop orgs with no members. Compute MANTLES: for every LEGEND whose claim verb is 'retake' or 'hold', {claim, predecessor_uid: THE LEGEND'S OWN uid, civilization_id, vacant_since_age: born_age}. Compute diagnostics (A33). Emit.

A32. BONDS (`facts.bonds`). `pretenders` = {lost ruin uid → the pretender} (last writer wins). Iterate people in cast order:
      warlord → for each city it defeated, if a pretender holds that ruin: edge {a: heir uid, b: warlord uid, kind:'rival', from_event: war_id}.
      domain_holder or magister with a `lost` → if a pretender holds that ruin: {a: heir, b: this person, kind: 'rival' for a domain_holder and 'kin' for a magister, from_event: the ruin id}.
    Then for each dread, for each city it destroyed with a surviving pretender: {a: heir, b: dread uid, kind:'rival', from_event: 'ruin-' + city uid}.
    Then, with `warlords_by_city` = {victor_uid → warlord} and `sovereigns_by_realm` = {realm_uid → sovereign} (last writer wins in both), iterate people again:
      a champion whose home city is a warlord's seat → {a: champion, b: warlord, kind:'betrayed', from_event: the warlord's first deed's event id}.
      a council member whose realm has a sovereign → {a: council, b: sovereign, kind:'ally', from_event: THE HOME CITY UID (not an event id — carry this oddity as-is)}.
      anybody carrying 'mentor:successor' → the pupil is `min(living compatriots born later, key=(born_age, uid))`; edge {a: mentor, b: pupil, kind:'mentor', from_event: the mentor's first deed's event id, or their own uid when they have no deeds}.

A33. DIAGNOSTICS (`role_diagnostics`). `kinds` = {role → {role}} for every key in the precipitation policy, with the single override kinds['diaspora'] = {'prophet','exile','founder'}. Aggregate the roll ledger by `kind` into {candidates, placed, best chance}. `sources` (a second, independent count of "how many world records each declared role had to work with, before any roll") = heir: ruins; warlord: ruins that lost a recorded war; dread: ruins a beast destroyed; domain_holder: ruin key points standing in a ley network; magister: self_magic ruins; college_magister: living colleges; camp: ruins; sovereign: realms (recomputed by calling build_realms a second time); council: Σ over living cities of the number of seats its class declares; diaspora: living cities with a diaspora reason; champion: living cities + beast-taken ruins; reeve: hamlets; castellan: fortresses; harbourmaster: ports; keeper: shrine sites; cult: cult sites. Emit one row per role in SORTED ROLE ORDER with a `reason` sentence chosen as: placed > 0 → "<placed> of <candidates> candidates precipitated"; candidates > 0 → "<n> candidate(s) rolled and <it|none> did not precipitate; the best chance offered was <best>"; sources > 0 → "<n> <phrase> were read and none produced a candidate"; else → "no <phrase> in this world, so nothing rolled". The design intent, carried verbatim in spirit: a consumer could not previously tell "this world has no Dread because it has no beast-ruined city" from "the Dread role is not implemented" from "the Dread role rolled and lost", and the table is the POLICY'S list rather than the output's "so a role that stops firing cannot fall out of the report by falling out of the output."

## PART B — story_web.generate(world, policies=None)
################################################################

B0. VALIDATE (see PIPELINE POSITION). B1. LOAD AND LINT tropes, constraints, weights — same duplicate-key and non-finite-number rejection as the hero policies. The trope lint is strict and is the reason the catalogue can be trusted at runtime: exact field set {id,name,pull,requires,boosts,fits,claims,cast,acts,examples}; unique ids; `pull` exactly two axes, each finite and within ±1; at least one non-empty conjunction; EVERY token in every conjunction (after stripping a leading '!') must be a KNOWN FACT — a member of the 151-token vocabulary or a string beginning 'archetype:' with something after the colon; every boost key known and its factor finite and > 0; `fits` a list of non-empty archetype id strings; every claim verb in the eleven-word list (hold, retake, avenge, exploit, convert, protect, unify, kill, expose, overthrow, none); `cast` a non-empty subset of {person, dread}; EXACTLY THREE ACTS with unique ids, a non-empty title, a string prompt, a completion of kind 'target' with a non-empty target and state, an abandonment of kind 'deadline' with an integer days ≥ 1, and two to four options with unique ids, non-empty text and effect, and a delta of exactly {law, good} each within ±0.5; at least one non-empty prose example. The weights document's key set must be EXACTLY the fifteen listed fields.

B2. CAST = every person and every dread with `status == 'living'` (people first, then dreads, as concatenated), SORTED BY uid. `world_facts` is built once (B3). For each hero in that order:
    facts = person_facts(hero, bonds, heroes.final_age) ∪ world_facts.for_hero(hero)
    kind = 'dread' when role == 'dread' else 'person'
    For each trope IN CATALOGUE ORDER: skip when `kind` is not in the trope's cast. If the entry predicate holds, append a SPOKE {trope_id, name, weight, breakdown, angle}; otherwise append to `considered` {trope_id, missing}.
    `considered.sort(key=(len(missing), trope_id))`.
    If there are NO spokes, the hero is UNWOVEN: emit {uid, display_name, archetype, facts (sorted), nearest: the first three considered} and move on.
    `spokes.sort(key=(−weight, trope_id))`. The OFFERED spoke is spokes[0]; the rest are ARMED, in that same order.
    Build the slot table (B6), the threads (B7), and the three acts (B8).
    initiative_day = weights.initiative_days (90) + Rng::child(seed, "web-initiative-" + uid).randrange(0, 30) — a single draw in [0, 30), the ONLY draw in the entire package, and it decides nothing but the deadline stagger.
    Emit the web. Increment the offered-trope histogram.

B3. WORLD FACTS, computed once. Build: `uid_by_site_id` (settlement id → uid); `threat` by city uid; `deficit` by city uid from `humans.cores` (translated through uid_by_site_id); `coverage` by city uid from `seasonal_food.cities`; `surge` and `hollow` booleans from the lunar almanac (a SINGLE event anywhere sets the flag for every hero — the limits section calls this deliberately coarse); `node_intensity` by node id; the living uid set, the dread uid set, whether any dread lives; `resting_relics` = the ruin uids of relics with a null holder; `camp_ruins`; `mantles` = civilization → set of predecessor uids; `realm_count`; `sovereign_civs`; `tyrant_civs` (living sovereigns or warlords whose archetype is 'tyrant'). Then PER HERO: with a home city — 'world:war_pressure' when war_pressure > 0, 'world:war_recent' when wars_recent > 0, 'world:enemy_living' when the flag is truthy, 'world:war_risk' when war_risk > 0, 'world:war_hunger' when war_hunger > 0, 'world:threatened' when regional_threat ≥ 0.5, 'world:food_deficit' when the rural core deficit > 0, 'world:famine' when the city has a coverage row BELOW `famine_coverage` (0.5). The comment on the last: "A famine is a year the city cannot feed itself, read from the seasonal food model, not the structural deficit diagnostic (which marks nearly every city that lacks farms)." Unconditionally: 'world:surge', 'world:hollow_night'; 'world:node_intense' when the hero holds a node whose intensity ≥ `node_intense_threshold` (1.5); 'world:rival_living' when any of the hero's rivals is alive; 'world:rival_dread' when any is a living dread; 'world:relic_resting' and 'world:camp_at_lost' keyed on the hero's lost ruin; 'world:mantle_open' when the hero's civilization has an open mantle held by somebody else; 'world:other_realm' when there are ≥ 2 realms; 'world:dread_living'; 'world:realm_has_sovereign'; 'world:realm_tyrant'.

B4. PERSON FACTS. Start from the hero's `selectable` list verbatim. For every WAR deed add 'war:veteran', plus 'war:victor_recent' (role credited) or 'war:defeated_recent' when the deed's age equals the cast's final age. Add 'role:<role>', 'status:<status>', 'tier:<tier>' when it is one of the three bands, 'archetype:<id>' when set, 'claim:<verb or "none">', 'bond:<kind>' for every bond edge naming this uid with a known kind, 'home:set' or 'home:none', 'lost:set', 'presence:<situation>' when the situation is one of the nineteen known ones, 'faces:two' when the hero has more than one face, 'companion:eligible' when the companion block says so.

B5. PREDICATES AND WEIGHT. `holds(token, facts)` = membership, or NON-membership when the token starts '!'. `eligible(requires, facts)` = any conjunction holds entirely. `missing(requires, facts)` = the failing tokens of the conjunction with the FEWEST failures, first such conjunction winning (strict `<` over catalogue order); an empty list when something holds.
    weight = round(boosts, 4) × round(alignment_fit, 4) × archetype_fit × claim_fit, the product itself rounded to 4 dp — deliberately computed FROM the rounded parts "so the exported breakdown reproduces it".
      boosts = Π of the trope's factor for every boost fact the hero carries; `boosted_by` records which ones applied, in the trope's boost-table order.
      alignment_fit = max(fit_floor 0.25, 1 + fit_gain 0.75 × (pull·alignment) / max(|pull|, pull_floor 0.5)). A spoke pulling the way the hero already leans is favoured; an opposed one is damped, never removed.
      archetype_fit = fits_factor 1.6 when the hero's archetype is in `fits`, else 1.
      claim_fit = claim_factor 1.5 when the hero's claim verb is in `claims`, else 1. (Two tropes — The Absolute, The Ascension — declare an EMPTY claims list on purpose, so "they only win when the log is quiet.")
    angle_degrees(law, good) = round(degrees(atan2(law, good)) mod 360, 2) — good to the right, lawful up, counter-clockwise from good.

B6. SLOTS (`bind.slots_for`). A dictionary with a fallback map for the nine named slots: hero→"the hero", target→"what they claim", rival→"their rival", home→"their home", lost→"what was lost", relic→"the relic", realm→"their realm", realm_other→"the neighbouring realm", species→"the beast", lost_other→"the city they took"; an UNKNOWN slot renders back as the literal `{key}`. Filled from the record: hero = display_name or uid; target = claim.target_name; rival = the display name of the FIRST entry of `rivals`, falling back to the uid, or, when the hero has no rivals but claims kill/avenge/expose/overthrow, the claim target's name; home = home.name; lost = lost.name, and when a relic rests in that ruin, relic = its name; realm = the hero's realm name, and realm_other = the alphabetically FIRST other realm name (or, when the hero has no realm, the alphabetically first realm name of all); species (dreads); lost_other = the first defeated city's name. `fill(template, slots)` substitutes and then upper-cases the first character of the result.

B7. THREADS (`threads.threads_from`). For every OTHER trope whose cast admits this hero, find the CHEAPEST way in over its conjunctions:
      gaps = the conjunction's tokens that do not hold.
      no gaps                                        → {kind:'open'};      facts after = unchanged
      exactly one gap and it is a `claim:` token      → {kind:'claim', verb}; facts after = all facts minus every `claim:` token, plus the new one
      one or two gaps, none negated, all in `gainable_features` → {kind:'feature', facts: those tokens}; facts after = facts ∪ those
      anything else                                  → this conjunction offers no way in
      Keep the minimum of (RANK[kind], number of gained facts) with RANK = {open 0, alignment 1, claim 2, feature 3}, first conjunction winning ties.
    Then: weight = the trope's weight evaluated with the AFTER facts and, for a claim thread, a hero whose claim verb has been swapped — "so the order reflects where the hero would land".
    For an `open` thread, test the pull against the hero's CURRENT alignment: `opposes(pull, alignment)` computes the per-axis contribution pull[axis] × alignment[axis] for good and law; when their SUM is ≥ 0 the pull agrees and the thread stays open; otherwise the thread is re-labelled {kind:'alignment', axis: the axis with the smaller contribution (ties broken alphabetically, so 'good' before 'law'), toward: 'up' when that axis's pull is positive else 'down'}, and it is CUT with "drift locked by archetype" when the archetype's constraints lock drift. Only an open way in is checked against the pull — a claim or feature thread already names the one change it needs and the walker re-evaluates alignment when it arrives.
    For a `claim` thread: cut with "claim locked by archetype" when claim_locked, else "claim verb <v> not allowed by archetype" when `allowed_verbs` is a list not containing it.
    Sort by (RANK of the FINAL condition kind, −weight, trope id) and truncate to `max_threads_per_act` (6). Note that threads belong to the WEB, not to one act, despite the policy field's name.

B8. ACTS. For each of the offered trope's three acts, in order, emit {id, title, ring: 1-based index, prompt: fill(act.prompt, slots), completion: a deep copy, abandonment: a deep copy plus `implicit: ['protagonist_dead','target_gone']`, options: [{id, text: fill(option.text, slots), delta: a copy, effect}]}. The RESTING HOOK is {trope_id, act_id: the FIRST act's id, prompt: the first act's filled prompt, expires_day: the initiative day}.

B9. REACHABILITY. NEVER_COMPUTED = {'dread:person_shaped', 'ally:lost', 'deeds:two_schools'} — features the archetype catalogue reserves but no well computes (verified against the hero generator on 2026-09-19). A trope is REACHABLE when any conjunction consists entirely of tokens that either start 'archetype:' or, with any leading '!' stripped, are not in that set. Unreachable trope ids are exported sorted, "listed in the ledger as unreachable rather than hidden". With the current 51-trope catalogue every trope has at least one satisfiable entry, so the list is empty — but the mechanism must be ported, because it is what tells a consumer a documented arc cannot fire.

B10. `report.py` is a CALIBRATION TOOL, not part of the pipeline: it re-reads a finished block and flags `generic` (a generic seat spoke — the_court, the_reign — beat an eligible spoke naming the hero's archetype), `unfit`, `claim`, `close` (runner-up within 10 %) and `unwoven`. Port it only if the C++ side wants the same tuning loop.

## Random streams

Both packages use only NAMED CHILD STREAMS derived from the world's master seed; no stream is ever carried between candidates, so a draw added to one person cannot move another. In the reference this is `random.Random(child_seed(master, domain, variation))` where `child_seed` takes the first four bytes of `sha256("tectonics-v1:<master>:<domain>:<variation>")` big-endian; in the C++ port it is `fwg::Rng::child(master, domain, variation)` with `variation` left at 0 everywhere. The literal domain strings ARE the replay contract — changing one renames a stream and silently rerolls that subsystem — so port them verbatim.

hero_generator streams, one per purpose per subject:
  "hero-roll-<candidate uid>"      — 1 draw (`random()`), once per evaluated candidate INCLUDING camps. Count = total candidates, data-dependent: ruins × (1 heir + maybe 1 domain_holder + maybe 1 magister + maybe 1 camp + maybe 1 fallen champion) + warlords + dreads + realms + Σ council seats + diaspora cities + reach-admitted cities + hamlets + fortresses + ports + religion sites.
  "hero-alignment-<uid>"           — 2 draws (`uniform` × 2, LAW FIRST then GOOD), once per precipitated person and per dread.
  "hero-archetype-<uid>"           — 1 draw for the weighted card selection, plus 0–2 more inside `intensify` (only when an axis value is EXACTLY 0.0, which is rare but reachable, and only for the three cards that declare an intensity). Good is signed before law.
  "hero-name-<uid>"                — a VARIABLE number: the heritage name generator draws first (template weighting, element choices or syllable draws, inside a bounded redraw loop, so the count depends on the tongue and on rejections), then exactly one `choice` for the epithet. THIS IS THE ONLY DATA-DEPENDENT DRAW COUNT IN THE PACKAGE, and because the two consumers share one stream, any change to the heritage name algorithm moves every epithet.
  "hero-face-<uid>"                — 1 `choice` for a public/true card's cover role, or 2 `uniform` draws (law then good) for a first/second card. No draws for calm/unleashed or for a single-faced card.
  "hero-place-<uid>"               — 1 `choice` over ['captive','hidden'], only for a dispossessed person placed at a camp.
  "hero-seed-<uid>"                — 1 `getrandbits(32)`, once per precipitated person and per dread, exported as that record's own sub-seed for consumers to branch from.

story_web streams:
  "web-initiative-<uid>"           — 1 `randrange(0, 30)` per WOVEN hero. Nothing else in the package is random: "No draw decides an assignment; the seed only staggers initiative deadlines." An unwoven hero consumes no draw.

Order of consumption within `_finish_person` is: archetype stream (open, draw, maybe intensify) → alignment stream (opened FIRST inside derive_person, actually, so: alignment before archetype selection) → name stream → face stream → seed stream. Because every stream is independent and named, this order does not affect values; it only matters if a port tries to share one stream, which it must not.

Draw-count summary: O(candidates) roll draws + O(precipitated) × (2 + 1 + variable + 0..2 + 1) + O(woven) initiative draws. On a reference world this is a few hundred draws in total — negligible cost, so a port should optimise for clarity, not for stream economy.

## Ordering hazards

This is the longest list in the spec, because both packages are dominated by container order reaching output. Every item below was verified in the source.

HERO GENERATOR
1. `people.sort(key=(born_age, uid))` (step A15) fixes the cast order that fame, cross-cutting features, the seated/unseated archetype passes, bonds, hooks and the exported array all inherit. A C++ port must sort on the same composite key with the same string comparison (byte-wise, not locale-aware).
2. Well execution order (ruins → magic → cities → guilds → countryside → ports → shrines) sets the `rolls[]` array order. `rolls` is exported and consumed by diagnostics, so it is output, not scratch.
3. Within the ruins well: heirs roll in RUIN EXPORT ORDER; warlords roll in SORTED KEY ORDER (`sorted(warlords)` over the `"<age>-<victor uid>"` strings — a LEXICOGRAPHIC sort, so age 10 sorts before age 2); dreads roll in SORTED NEST ID ORDER. The warlord one-per-city reduction compares the tuple `(born_age, key)`, again mixing a numeric and a lexicographic component.
4. `realm_by_city` is built by iterating realms then their `city_uids`; a city appearing in two cultures resolves to the LAST realm written. Likewise `wars_by_defeated` keeps the LAST war naming a given defeated uid, `pretenders` keeps the LAST pretender per ruin, `warlords_by_city` and `sovereigns_by_realm` keep the LAST of each.
5. `magic.networks` is iterated in DICT INSERTION ORDER to build the node→(school,node) map, so a node id present in two schools resolves to the later school. The `intensity` index in `hooks._index` instead iterates `sorted(networks.items())`. The two disagree by construction — flag it.
6. `_dominant_school` iterates `sorted(layers)` with a STRICT `>`, so ties go to the alphabetically first ley school.
7. `policy.seats[city_class]` is a LIST and its order is the candidate order, the roll order and the council `members` order.
8. Archetype selection walks `cards` in CATALOGUE ARRAY ORDER; the weighted walk subtracts in that order, so the array order is observable in the chosen card for a given draw.
9. `persona._line` falls back to "the first entry whose second character matches", which is dict-insertion order over the card's `lines` object — so the JSON key order of `lines` is load-bearing.
10. `persona.never` de-duplicates while PRESERVING the order core → law overlay → good overlay.
11. `naming.person_name` filters the epithet list to the usable ones IN TEMPLATE ORDER and then `choice`s over that filtered list, so removing an unusable template from the JSON changes which epithet a given draw selects.
12. `facts.person_log` sorts entries by `(age, event_id)` — a numeric then lexicographic composite.
13. `facts.bonds` iterates people twice in cast order; the resulting `bonds[]` array order is exported. `rivals`/`kin`/`allies` are then built through a SET and `sorted()`, so they are order-independent — but the `bonds` array itself is not.
14. `features.apply` groups living people by `realm_uid` in DICT INSERTION ORDER (which is cast order) and picks the first sovereign in each group; with two sovereigns in one realm the first in cast order wins.
15. `mantles` and `diagnostics` inherit cast order and sorted-role order respectively.
16. `orgs` order is: dynasties and councils in realm/city order from the cities well, then orders and remnants from the guilds well, with empty ones filtered out at the very end (preserving relative order).
17. `hooks._small_sites` deliberately writes the ORDINAL id first and the node anchor second so a collision resolves to the anchor. Reversing the two loops silently breaks every countryside hook.
18. `hooks._index['ruin_of_relic']` is built over `sorted(relics_by_ruin.items())`.
19. `intensify` signs GOOD before LAW; `faces` first/second draws LAW before GOOD; `derive_person` draws LAW before GOOD. Three different orders, all observable.
20. `nearest_city` and both `_nearest_threat` helpers minimise an explicit `(distance, id)` tuple precisely so the answer does not depend on list order — preserve the tie-break, do not "simplify" to a bare distance comparison.
21. `min(earlier, key=(-fame, uid))` in `_predecessors` and `min(..., key=(born_age, uid))` in the mentor bond are both composite; `max(members, key=(suitability, -node))` for a capital negates the node.

STORY WEB
22. `cast` is people-then-dreads concatenated and then SORTED BY uid — the sort makes the concatenation order irrelevant, but the sort itself is required.
23. Tropes are evaluated in CATALOGUE ARRAY ORDER, which sets the `considered[]` pre-sort order and, through the `missing` helper's strict `<`, which conjunction is reported as nearest.
24. `spokes.sort(key=(-weight, trope_id))` — the trope-id tie-break is the documented rule ("ties break on trope id") and is what makes the offered hook stable when two weights round to the same 4 dp value.
25. `considered.sort(key=(len(missing), trope_id))` then truncated to 3 for an unwoven hero.
26. `threads` sorts by `(RANK[condition kind], -weight, to)` then truncates to 6. The RANK is read from the FINAL condition, after an open thread may have been rewritten to `alignment`, so the rewrite changes the sort position.
27. `_way_in` scans a trope's `requires` in array order with a strict `<` on `(RANK, len(facts))`, so the FIRST cheapest conjunction wins.
28. `opposes` breaks a tie between the two axes with `min(('good','law'), key=(contribution, axis))` — alphabetical, so 'good' wins an exact tie.
29. `weight`'s `boosted_by` list is in the trope's boost-object key order, i.e. JSON insertion order.
30. `slots_for` picks `rivals[0]` (the hero's alphabetically-first rival, since `rivals` was sorted) and `sorted(realms.values())[0]` for `realm_other`.
31. `summary.offered` is exported as `dict(sorted(histogram.items()))` — key-sorted, not insertion-ordered.
32. `unreachable_tropes` is `sorted(...)`.
33. Both packages' `selectable` / `facts` arrays are `sorted()` sets, so a port using an unordered set must sort at the export boundary.

CROSS-CUTTING: `sorted()` on these strings is CPython's byte-wise comparison of UTF-8. All ids here are ASCII, so `std::sort` with `std::string::operator<` matches. Names and prose are NOT sorted anywhere, so no collation question arises.

## Edge cases

HARD FAILURES (these raise and become a `status: 'failed'` block; a port must reproduce the failure, not paper over it):
- `config.seed` absent or not exactly an integer (a float or a bool is rejected).
- `history.ages` absent or not a list.
- Any of `ruins`, `settlements`, `civilizations`, `humans`, `beast_nests` missing as a key (an EMPTY one is fine).
- A policy document with a duplicate object key, a non-finite number, or a missing/non-positive integer `revision`.
- Any archetype card or trope failing its lint (the lints are long and strict; see ALGORITHM A1 and B1).
- A person for whom NO archetype precondition holds: `ValueError("no archetype precondition holds for <uid>: <sorted features>")`. In practice every person carries a `role:` token and several cards accept a bare role, but a policy edit can reopen this. A DREAD with no eligible card does NOT raise — archetype, archetype_name and persona simply stay null.
- A person with no `civilization_id` reaching the namer raises rather than defaulting to human. This is deliberate: the silent fallback it replaced gave four peoples human names for their entire existence.
- A quest hook whose computed verb is outside the ten-word vocabulary raises.
- story_web: a missing `heroes` block, or one whose `status` is not 'ok', or one lacking any of people/dreads/bonds/realms.

DEGENERATE WORLDS THAT MUST PRODUCE A VALID BLOCK:
- No ruins → no heirs, no warlords, no dreads, no camps, no relics, no domain holders, no ruin magisters, no fallen champions, no shrines (every religion site needs a ruin). The diagnostics row then reads "no ruins in this world, so nothing rolled". This is the common case for the Dread on real worlds: measured on seed 42 size 33, all 39 ruins fell to war, water or air, so `heroes.dreads` is empty because no candidate was ever built.
- No living cities at all → `nearest_city` returns null everywhere; pretenders are legends; dispossessed people with no camp stay legends; `settlements.sites` empty means no sovereigns, councils, champions, reeves, castellans or harbourmasters.
- No cultures → no realms → no sovereigns, and every `realm_uid` is null.
- A culture whose `city_ids` name no living city is skipped entirely.
- A realm whose capital is not in the living-city map is skipped by the cities well (its `sovereign_uid` stays null).
- A city class not in the seats table (or a missing `city_class`) yields an EMPTY seat list and no council.
- A nest with no `x`/`z` is skipped by every grid-metre search but still participates in great-circle searches; a nest with `range_m` ≤ 0 contributes no pressure.
- A ruin with no `direction` makes the shrine well skip the home and target lookups (it explicitly tests `'direction' in ruin`).
- A religion site whose `ruin_id` names no ruin is skipped.
- `layers` missing, or a `[z][x]` index out of range, or a non-subscriptable layer: every ley read is wrapped and swallowed, costing one feature. Same for the dominant-school scan.
- `spacing_m` absent → 1000.0; `globe_radius` absent → 1.0 (which makes every great-circle distance an ANGLE in radians, so the champion reach test compares radians against metres and admits essentially nothing — a world without `effective_config.globe_radius` silently produces no champions).
- `nest.range_m` absent → 1000.0 in the champion and reeve reach tests and in dread reach; `nest.tier` absent → 1 for a champion's deed, 5 for a dread and for a fallen champion.
- A person with no deeds: `person_magnitude` returns 0 (plus any seat/sovereign term), `fame` is 0 × (1+reach) = 0, tier 'notable'; `roll`'s `first` lookup falls back to `{}` so `event_id` and `age` are null in the ledger; the mentor bond falls back to the person's own uid as `from_event`.
- A magister from a self_magic ruin whose key point does NOT exist has `node_id` null, so the ley hook branch is skipped AND the college branch does not apply — that person emits NO hooks at all.
- A council member seated anywhere but market_steward or commander emits no hooks.
- A dread never gets rivals/kin/allies, a claim, a civilization_id or faces, so in story_web it always carries `claim:none`, `home:none`, no `bond:` facts, and `mantles.get(None)` is consulted for its (absent) civilization.
- An `unwoven` hero produces no acts, no threads and no initiative draw.
- `mean_spokes` is 0.0 (not NaN) when there are no webs.
- `alignment_fit` with a zero pull: |pull| is floored at `pull_floor` 0.5 and the dot product is 0, so the fit is exactly 1.0 — a neutral-pull trope is never favoured or damped.
- `intensify` on an axis that is EXACTLY 0.0 consumes a coin-flip draw; this is the only place a draw depends on a computed float being precisely zero, and after a 3-dp rounding it is reachable.
- `missing()` returns `[]` when some conjunction holds — the caller only uses it in the non-eligible branch, but a port must not assume non-empty.
- An org with no members is dropped; a camp with no leader simply lacks `leader_uid`.
- `short_name` on a name containing " City" more than once strips only the FIRST occurrence.
- `species_from_nest_id` on an id with ≤ 2 dash-separated parts, or not starting 'nest', returns the whole id space-joined and capitalised.

WORLD EDGES AND POLES: neither package touches the grid seam or the poles directly. Grid distances are plain Euclidean hypot on `(x, z)` node coordinates times `spacing_m` — they do NOT wrap at the longitude seam, so a hamlet near column 0 and a nest near column n−1 are measured the long way round. That is the reference behaviour and a port must reproduce it (or flag the change deliberately). Great-circle distances go through the `direction` unit vectors and are seam-free, and the `acos` argument is explicitly clamped to ±1 against floating-point overshoot. No code here reads row 0 or row n−1, so the pole-duplication convention of `fwg::Grid` never bites; the only layer reads are `layers[school][z][x]` at city and college positions, which are interior by construction.

## Reasoning worth preserving

These are the comments that record a decision, a measurement or a failure that exists nowhere else. They are the most expensive content in the two packages.

ON THE THESIS. "A character is a named handle on an event the world already recorded. Nothing is rolled from a template: the heir points at the ruin, the warlord at the war, the Dread at the nest the ruin's own evidence names." And: "Nothing is planned for them: the log, the situation, the faces and the hooks are the data an orchestrator improvises from." The `LIMITS` string is equally load-bearing: "An artistic reading of the exported history, not a demographic claim… nothing here acts, fights, changes a node, or scripts what a person will do next."

ON THE ROLL LEDGER. "A candidate rolls exactly once, seeded from its uid, and the ledger keeps the outcome either way, so the block records what history could have produced and did not." This is why `rolls[]` exists at all.

ON THE ONE-WARLORD-PER-CITY RULE. "A city remembers one warlord: the most recent victor. Earlier victors' wars stay in the city's history and the survivor's deeds; they do not each precipitate a person."

ON THE COUNTRYSIDE ANCHOR (the single most detailed rationale in the package, and a repeat of a mistake the repo has made): "`humans.hamlets[].id` and `humans.fortresses[].id` are **ordinals**. `terrain_humans.record()` builds `f'{kind}-{number}'` where the number is the position in the accepted list, and fortresses are accepted in descending `defence_score` over a `strategic` map rebuilt from the road graph every age. Cities die, roads move and war history reweights the score, so both the membership and the ordering change at every age boundary: `fortress-36` names different ground after an advance, and the person built on it is renamed although nothing about their ground changed. Worse, the old uid still resolves — to a real person at a real fortress, and the wrong one, with no error." And: "The terrain node does not renumber. `-node-` is written into the key rather than left implicit because `fortress-13` and `fortress-node-13` would otherwise read alike and mean different things, which is how a consumer joins the wrong rows without an error." And the MEASUREMENT: "On the seed-42 size-33 sample world no fortress currently shares one with a hamlet (0 of 56), but 18 nodes are shared across the two kinds on the size-65 sample, so the prefix is load-bearing at other sizes even where it looks redundant at this one." And: "A site with no `node` keeps its ordinal id: there is nothing stabler to key it on, and a world whose small-site records have lost their node is broken upstream of this package." And at the call site: "All four uses of the anchor, together. Repairing one leaves three ways to join the wrong row, and three of them are the ones a story layer, a quest and a save file reach for."

ON THE HOOK LOOKUP FOLLOWING THAT ANCHOR: "That function is imported rather than its spelling copied, so this lookup follows it wherever it goes; restating the format here is how the two would drift apart and every countryside hook would quietly read `target_not_found`." And on the dual-key table: "The ordinal is written first and the node key second, so a collision between the two spellings resolves to the node key, which is the one that survives an age."

ON THE ` City` STRIP: "`heritage.settlement_name` replaced the round-robin that appended ` City`, so on any generated world this is the identity. It still fires on the synthetic worlds in `tests/test_hero_generator.py` and on `Fixtures/hero-generator-v1.json`… That is why it is still here: the removal is a fixture change, not a one-line change."

ON NAMES KEYED BY CIVILIZATION, NOT RACE: "keyed on the parent race, a desert human and a cold human drew from one table, and the four peoples with no table of their own — tidekin, gnome, hill_dwarf, frosthold_dwarf — fell through to the human one without comment." And: "A record missing `civilization_id` raises instead of falling back. The silent fallback this replaces is the defect — it gave four peoples human names for as long as they have existed, and a loud failure is the only way that does not happen again." And on why epithets stay English: "They are what the player reads about a hero, and `Torsunn the Unyielding` is the intended effect."

ON THE TWO CASING BUGS IN `_fill`: "`{school}` renders 'the fire focus', `{School}` renders 'the Fire Stone'. Without the second form a school name filled mid-title reads as a typo — `Keeper of the fire Stone`." And: "Only the first letter is raised: `str.capitalize` would lower the rest and turn a seat like `Court Mage` into `Court mage`." And on the placeholder fold: "Without the fold, a capitalised token resolves to no context value, the template is judged unusable and is quietly dropped from the draw — the epithet would not render wrong, it would never be chosen."

ON ALIGNMENT. "Jitter may move a value but never across zero once a deed put it on one side." And: "Centres per civilization are authored flavour, not derived from the registry; deed shifts decide a sign that jitter may never flip." And on the ordering of the two passes: alignment is derived BEFORE the archetype "so a card is chosen for a person who already has a moral colour", and intensity is applied AFTER. And on priors: "Nothing is clamped by alignment: a prior only changes frequency" — "a Conqueror is more often lawful, never only lawful. Every archetype exists in all nine cells."

ON FACES: "the mask is always visibly good" (the public face's good axis is forced to at least 0.5 in magnitude). And the purpose: "a public face speaks with a Good overlay while the true face underneath speaks with an Evil one."

ON PERSONA `never`: "`never` is the union of every hard line, so a downstream proposal that crosses one can be rejected mechanically."

ON THE SEATED-FIRST TWO-PASS: archetypes are chosen "seated people first so a Tyrant can make Rebels", and `mark_rebels` only touches people who have not yet been finished.

ON FAME CALIBRATION: "A capital heir with a capital seat lands near 19; a victor who took a capital in an international war near 38. Legendary is reserved for the latter kind of deed." And the invariant a test holds: "raising the class of the fallen city or the tier of the beast must raise the fame".

ON `villain:prior_age` — the longest disclaimer in the repo, held in place by a dedicated test file, and it must survive the port because the word collides across package boundaries: "`icarus_sim.terrain_villains` owns that word in the world model: a field with a continuous tier, a reach in metres, a seat and held ley nodes, at most one per cultural region, published in the `villains` block under its own schema. This is a feature token on an ordinary person, and it means only what the line below tests — a pretender whose people founded a city again after they were born, so their claim was overtaken while they lived. It carries no tier, no reach, no region and no seat, and a world can be full of these with an empty `villains` block. Filtering `selectable` for it to find 'people connected to a super villain' returns dispossessed claimants and nothing about super villains at all, with no error; and it is NOT evidence that a super villain stood here in a prior age, which is a question `villains.fallen` answers and this does not." The docs add: "The one field name the two share is `tier`, and it means two things."

ON THE QUEST CONTRACT: "The generator emits an anchor, a verb and a difficulty; the consuming game prices the reward. There is no `reward`, `loot` or `xp` field." On the verb list living in code rather than policy: "It is a closed contract rather than a tuning table, which is why it is code and not policy: a new verb needs a new hook branch to emit it." On the banding: "The banding is `floor(x + 0.5)` rather than `round`, because CPython rounds halves to even and a rubric that sends 2.5 down and 3.5 up reads as arbitrary to anyone checking it by hand." On the pressure exemption: "The rubric reaches 5 only through what stands at the target, never through the ground around it, so a long walk past a lair can never turn an errand into a campaign threat," and "its tier is already the whole answer and its own `range_m` would otherwise count it a second time." On a zero pressure: "Nothing reaching it is 0.0, which is a statement about the ground rather than a missing value: quiet country is the common case and it should read as quiet." On unsited hooks: "`ley_node_has_no_site` is the honest one — `magic.networks.<school>.nodes[]` carries a direction and an intensity and nothing a player can stand in front of. The other two say the world moved out from under the hook, which is a world change and not a defect." On the `target` field: "A nest effect names `nest_id`, so reading `uid` or `node_id` alone left every slay hook pointing at nothing." MEASUREMENT, seed 42 size 17, generator 16: "46 hooks, difficulty 1×3 / 2×29 / 3×13 / 4×1, 42 sited and 4 `ley_node_has_no_site`. Nothing reaches 5 on that world because nothing on it targets a lair… These are current counts for one seed at one size, not invariants."

ON THE `_index` KEY DISCIPLINE: "No two blocks name their key the same way, so each row states the exact field it joins on rather than trusting a shared convention: `ruins` by `uid` (its `id` is the `ruin-`-prefixed form the ley key points use), settlements by `uid`, ports, shrines and colleges by `id`, and hamlets and fortresses by both spellings of theirs."

ON THE SHRINE'S MEASURING RECORD: "`religion.sites` carries a node and no grid position; the ruin it was born of carries both, and is the same ground."

ON DIAGNOSTICS: "This is the half `rolls` cannot answer. The ledger records every candidate that was *evaluated*, so it distinguishes a role that rolled and lost from one that placed — but a role with no row in it is indistinguishable from a role that does not exist, and that is exactly the Dread's case." And: "the phrase beside it names what was counted rather than restating the well's gate — a second copy of a predicate answers a slightly different question sooner or later." And: "`role` is the key in `wells.json`'s `precipitation`, so the table is the policy's own list and a role that stops firing cannot fall out of the report by falling out of the output." And: "One row is not a person. `camp` precipitates a place: its `placed` counts rows in `camps`, not in `people`." MEASUREMENT: "It exceeds `candidates` wherever the well walked records that did not qualify — 35 living cities read for 2 champions, because only two stand within a dangerous nest's reach." And the honest limitation: "What `diagnostics` does not establish is whether a zero is *correct*: it reports that no ruin named a beast, not whether a world of that size and age ought to have produced one. A role gated on something that never fires would report faithfully and look exactly like a world that simply lacks the ground."

ON PLACEMENT: "Give the dispossessed somewhere to stand; a person with nowhere at all stays a legend… None of this is a script; it is where the person is standing when the story starts." And: "The captive necromancer of the original brief is one thing this can produce; it is not scripted, and most worlds will produce something else."

ON STORY WEB'S DEFENSIVE READS: "Every read below skips a malformed row rather than failing the block: a bad row costs one fact."

ON FAMINE vs DEFICIT: "A famine is a year the city cannot feed itself, read from the seasonal food model, not the structural deficit diagnostic (which marks nearly every city that lacks farms)."

ON WEIGHT ROUNDING: the product is computed "from the rounded parts, so the exported breakdown reproduces it" — a consumer must be able to re-derive the weight from the three exported factors.

ON THREADS: "Only an `open` way in is checked against the pull: a `claim` or `feature` thread already names the one change it needs, and the walker re-evaluates alignment when it arrives." And on the thread weight: "The thread's weight is the trope's weight *after* the condition holds (the changed verb or the gained facts applied), so the order reflects where the hero would land."

ON UNREACHABILITY: "A trope whose every conjunction needs a feature nothing computes is documented but cannot fire," and it is "listed in the ledger as unreachable rather than hidden". The NEVER_COMPUTED set carries its own provenance: "checked against Sim/hero_generator on 2026-09-19".

ON THE PERSONALITY SPOKES: The Absolute and The Ascension "carry no claim fit so they only win when the log is quiet."

ON ISOLATION: story_web's fact vocabulary is "copied rather than imported so this package reads only the block" — the duplication is deliberate and a port must decide consciously whether to keep two copies or one shared header (see OPEN QUESTIONS).

ON THE SHARED SEED HELPER: "It is the generator's expression verbatim, including the literal domain prefix, which is part of the replay contract and not a detail: changing it renames every stream in every package at once." The per-package copies were removed in favour of one implementation with one pin.

## Notes for the C++ implementation

WHAT THIS PORT IS. These two packages are pure data transformation over a JSON-shaped world: no grids, no noise, no physics, no floating-point accumulation that matters. Almost none of `fwg::Grid`, `sphere_grid`, erosion or water is relevant. What IS relevant is that the C++ side currently has no typed world blocks for ruins, settlements, wars, nests, ley networks, religion, humans or fisheries — every one of those must exist before this subsystem can be written. This is therefore the LAST thing in the 16-stage ladder to port, and the spec assumes stages 6–15 have already produced typed structs for the records listed under READS.

REPRESENTATION. Model each block as a plain struct with `std::vector` members, not as a generic JSON tree. A `Person` struct with ~40 fields, many optional, is the right shape; use `std::optional<T>` for the genuinely nullable ones (`home`, `presence`, `lost`, `realm_uid`, `predecessor_uid`, `school`, `node_id`, `seat`, `nest_id`, `site_name`, `archetype`) rather than sentinel strings, and serialise `std::nullopt` as JSON `null` through `fwg/json.hpp`. The mutable feature set during construction should be `std::set<std::string>` (ordered, so `selectable` is just a copy), NOT `unordered_set` — the export is sorted and an ordered set makes that free while also making iteration deterministic during debugging.

STRING IDS. Every id here is a string and every join is a string map. Use `std::map<std::string, const Record*>` (ordered) rather than `unordered_map` wherever the map is ITERATED (the node→school map, the trade counts, the mantle table); `unordered_map` is fine where it is only looked up. Where the reference relies on "last writer wins" in a dict comprehension, `operator[]` assignment reproduces it exactly; where it relies on "first writer wins", use `try_emplace`. Both patterns occur — check ORDERING HAZARDS item by item.

PYTHON IDIOMS WITH NO DIRECT EQUIVALENT:
- `dict` preserving insertion order. Four places rely on it (the ley network map, the `lines` fallback, the realm-group map in `features.apply`, the boost `boosted_by` order). Either use an ordered container or an explicit `std::vector<std::pair<K,V>>` for those four.
- `sorted()` over mixed-type tuples. Replace with explicit comparator lambdas returning `std::tuple` comparisons, e.g. `std::tie(a.born_age, a.uid) < std::tie(b.born_age, b.uid)`. Watch the NEGATED members: `key=(-fame, uid)` and `key=(suitability, -node)` need the sign flipped inside the tie, and `-node` on an unsigned type is a bug waiting to happen — keep node as a signed int.
- `min()`/`max()` with a key return the FIRST extremum in Python. `std::min_element`/`std::max_element` also return the first; `std::max` on two values returns the first only for `a < b` semantics. Prefer `*std::min_element` with an explicit comparator everywhere.
- Set algebra (`|`, `-`, `<=` for subset, `&`). `std::set` has `set_union`/`set_difference`/`set_intersection`/`includes`, all requiring sorted ranges; for the small sets here a simple loop is clearer and faster.
- `str.format_map` with a `__missing__` hook (the story-web binder). There is no C++ equivalent; write a small scanner that walks the template, extracts `{name}` tokens, and substitutes from a lookup with a fallback table. Do NOT reach for `std::format` — the templates contain apostrophes and arbitrary punctuation and are authored data, and an unknown slot must render back as the literal `{name}`, which `std::format` cannot do.
- The `_fill` double substitution (`{key}` and `{Key}`) in the hero namer is a different, simpler scheme: literal string replacement of two spellings per key, applied for EVERY context key in dict order. Reproduce it as written; do not unify it with the story-web binder, they behave differently on unknown tokens.
- `str.capitalize()` vs raising only the first letter — the code deliberately avoids `capitalize` in `_fill` and deliberately USES it in `species_from_nest_id`. Two different helpers.
- `round(x, n)` is banker's rounding in CPython; `difficulty` explicitly avoids it with `floor(x + 0.5)`. For the 3-dp and 4-dp roundings on alignment, chance, fame, weight and the roll ledger, the clean-rewrite licence means you may use `std::round(x * 1000.0) / 1000.0` (half-away-from-zero) — but DO round, because the rounded values are exported and, in story_web, the weight is computed from the rounded factors so a consumer can reproduce it.
- `getrandbits(32)` → `static_cast<std::uint32_t>(rng.next_u64() >> 32)` or a dedicated helper; the value is opaque (a sub-seed handed to consumers), so any 32-bit draw is fine.
- `randrange(0, 30)` → `rng.below(30)`.
- `random.choice(list)` → `Rng::choice`. Note that `heritage._pick_elements` calls `draw.choice(sorted(options))` — if heritage is ported, the sort is load-bearing.
- Exceptions: the `attach` boundary is a `try { ... } catch (const std::exception& e) { return failed_block(typeid_name, e.what()); }`. The reference formats the error as `"TypeName: message"`; pick a stable equivalent and keep it, because the lab displays it.

MAPPING TO THE EXISTING C++ CONVENTIONS:
- `fwg::Rng::child(master, domain, variation)` is exactly the right primitive and the domain strings port verbatim ("hero-roll-" + uid, etc.). Leave `variation` at 0; the reference never uses it here. Do NOT invent a fourth seed derivation — the memory rule and the header comment both say so.
- `fwg::Config` holds the resolved parameters; `config.seed` becomes the master. `globe_radius` and `spacing_m` come from the effective (metres) config, and BOTH are already metre-denominated in the C++ world, which matches the reference's post-scaling reads — see the note on reaches below.
- `fwg::World` gains two new typed blocks (`heroes`, `story_web`) alongside the layers. They are pure output; nothing in the core reads them back, which is what makes the try/catch boundary safe.
- `fwg::Grid` is used for exactly ONE thing in this subsystem: reading `ley_umbral`, `ley_infernal` and the ley_* family at `(x, z)` for the tainted-home and dominant-school tests. Note the reference indexes `[z][x]` — row then column — so map it to whatever `Grid::at` convention the C++ side uses and write a test for it, because the axes are easy to transpose silently. Nothing here touches the seam column or the pole rows.
- `fwg::sphere_grid` is NOT used. The great-circle distance here is computed directly from stored `direction` unit vectors (`R · acos(clamp(dot, -1, 1))`), not from the node graph. Reuse `fwg::vec3` for the dot product.
- The JSON writer in `fwg/json.hpp` must handle: nested objects three deep, arrays of objects, nullable numbers and strings, booleans, and prose strings containing apostrophes, em dashes and non-ASCII (the trope prose does). Check that it escapes correctly and emits floats with enough precision to round-trip the 3- and 4-dp values.
- SHA-256 in `fwg/sha256.hpp` is NOT needed for seeding (that is `Rng::child`'s job) but may be wanted for a provenance hash over the policy files.

POLICY LOADING. `fwg` has its own JSON writer but the header list shows no JSON READER. Two options: (a) write a small reader and keep the five + three policy files as data, which preserves the "policies are data so the cast can be rebalanced without touching code" property and keeps the 183 KB trope catalogue out of the binary's source; or (b) transcode the policies to C++ initialiser lists at build time. Option (a) is strongly preferred — the trope catalogue is authored content that will keep changing, `revision` numbers are exported and compared, and the LINTS (which are long and specific) are the contract that makes a half-authored trope fail at load rather than in play. If (a), the reader must reject duplicate keys and non-finite literals, because both are load-bearing policy-integrity checks.

HERITAGE. `heritage.person_name` and `heritage.realm_name` are a separate subsystem with their own genome data. The hero generator cannot be finished without them. If heritage lands later, stub them behind an interface that takes `(civilization_id, parent_race_id, Rng&)` and returns a string, and be explicit in the output that names are placeholders — do NOT silently fall back to a shared human table, which is precisely the defect the reference removed.

PERFORMANCE. Trivial at world scale: a few hundred people, 51 tropes, 32 cards. The only super-linear pieces are `_ruin_name`'s linear scan per warlord and `place`'s per-person rebuild of the ruins map — hoist both. `_realm_contested` walks every member city's war history per warlord; also fine, but hoistable. Everything else is a single pass or a sort.

TESTING. Because the port is functional-not-numeric, the useful tests are structural invariants, and the reference already names several: every hook's verb is in the vocabulary; every difficulty is an integer 1..5 and the set of difficulties on a real world has more than one member ("A rubric that answers the same number everywhere is not a rubric"); a slay hook's difficulty equals the nest's own tier for every tier 1..5; a keyed ley node sites at its ruin and a bare one reports `ley_node_has_no_site`; raising the fallen city's class or the nest tier raises fame; every precipitation role has a diagnostics row whether or not it fired; every trope token is a known fact; the two copies of the feature vocabulary are identical; the two copies of the verb list are identical.

## Open questions

1. `person.org_uid` IS ALWAYS NULL. `_finish_person` sets it to null and nothing ever writes it again, yet every org carries a `members[]` list of uids. The person→org back-reference is dead. A consumer wanting "which council is this person on" must scan `orgs`. Decide: populate it during the tidy pass (cheap, and probably the intent) or delete the field. Do not port it as-is without a decision.

2. A HERESIARCH IS INVISIBLE IN DIAGNOSTICS. `role_diagnostics` builds `kinds['diaspora'] = set(DIASPORA_ROLES.values())` = {prophet, exile, founder}. But the cities well rolls a diaspora leader under the PERSON'S ROLE, and a prophet whose mother civilization still stands becomes a `heresiarch`. That roll lands in the ledger with `kind: 'heresiarch'`, which no diagnostics row aggregates — so a precipitated heresiarch is counted nowhere, and the `diaspora` row under-reports both `candidates` and `placed`. The comment right above the line says "Four roles mint their roll under the person's own word rather than the policy key — a diaspora precipitates a prophet, an exile or a founder", which is a THREE-element list describing a FOUR-element situation. Almost certainly a defect. Fix by adding 'heresiarch' to the mapped set.

3. `predecessor_uid` MEANS TWO OPPOSITE THINGS. On a `people[]` record it is the uid of the LEGEND the person inherits from. On a `mantles[]` record it is the legend's OWN uid. Same field name, two referents, in one block. Rename one on the C++ side (e.g. `mantles[].held_by_uid`) or document it loudly; a consumer joining the two will silently build the wrong graph.

4. A COUNCIL→SOVEREIGN BOND'S `from_event` IS A CITY UID, not an event id. Every other bond's `from_event` is a war id, a ruin id or a deed's event id. Either it should be the capital's founding event or the field should be nullable here.

5. `weave` IS IN `dark_schools`. `weave` is also the DEFAULT school for a magister whose ruin records no `new_node_school`, and the default rendered school in a relic name. So a magister with no recorded school silently gains `school:dark`, which is the Deceiver and Temptation gate. Intended flavour or an accident of the default? It materially changes how many two-faced people a world produces.

6. THE LEY NODE MAP AND THE INTENSITY MAP DISAGREE ON ORDER. `wells/magic.candidates` builds its node→(school, node) map by iterating `magic.networks` in dict order; `hooks._index` builds its intensity map over `sorted(networks.items())`. A node id present in two schools therefore resolves to a different school in the two passes. Probably impossible in practice (node ids are school-scoped), but the inconsistency should be resolved one way in the port.

7. GRID DISTANCES DO NOT WRAP AT THE LONGITUDE SEAM. `_grid_metres` and `hooks._pressure` are plain `hypot(Δx, Δz) × spacing_m` on node coordinates. A hamlet at column 1 and a nest at column n−2 are measured the long way round, so a threat that is geographically adjacent reads as maximally distant. The great-circle paths in the same package are seam-correct. Decide whether to reproduce the bug or fix it (fixing it changes which hamlets are `threatened` and which hooks carry pressure, i.e. it changes difficulty numbers).

8. `globe_radius` DEFAULTS TO 1.0. On a world lacking `effective_config.globe_radius`, every great-circle "distance" is an angle in radians and is then compared against `range_m` in metres — so the champion reach test admits essentially nothing and the well silently produces no champions. A default of 1.0 for a RADIUS in a metre-denominated world is a trap; consider making it a hard failure in the port.

9. `heroes.archetypes.FEATURES` IS PURELY DOCUMENTARY. Unlike story_web's `known_fact`, which the trope lint enforces, nothing validates that an archetype card's `requires` tokens are in `FEATURES` — a typo in a card's precondition simply makes it unreachable, silently, forever. The set also contains several duplicated entries (`role:camp_leader`, `keypoint:ruin_born`, `stake:none`, `seat:none`, `school:dark`, `college:destroyed`, `sovereign:advised` each appear twice in the literal), which is harmless in a set literal but is evidence the list is hand-maintained. Add the lint in the port.

10. THE FEATURE VOCABULARY IS DUPLICATED ACROSS PACKAGES ON PURPOSE (82 tokens, verified identical today) so story_web reads only the exported block. In a single C++ library that isolation argument is weaker — the two "packages" become two translation units in one binary. Decide: keep two literal copies plus an equality test (preserves the stated design), or share one header (simpler, loses the isolation property the docstrings defend). This is a real design decision, not an oversight.

11. `weights.threshold` (0.34) IS NEVER READ by the compiler — it is a second copy of `hero_generator.alignment.THRESHOLD` maintained "for the lab and docs to quote". Two copies of a boundary constant across packages with no test tying them. Either tie them or drop one.

12. A SELF-MAGIC MAGISTER WHOSE KEY POINT DOES NOT EXIST EMITS NO HOOKS AT ALL. `node_id` is null, so the ley branch is skipped; the college branch needs a `college` field they do not have; no later branch matches `role == 'magister'`. They are a living, named, archetyped person with zero quest hooks. Intended (they have nothing to offer) or an unhandled case?

13. THE POOLED-EXECUTION QUESTION DOES NOT APPLY HERE. Neither package forks a process pool and neither reads `ICARUS_CITY_WORKERS`; that hazard belongs to the two settlement planners. Recorded so a porter does not go looking.

14. ORDERING OF `people` vs THE SORT. `people.sort(key=(born_age, uid))` happens AFTER placement but BEFORE fame, features, archetypes, bonds and hooks. Placement therefore runs in WELL order and can change a person's status and features; nothing downstream depends on placement order, but a port that moves the sort earlier for tidiness would change which camp an heir leads only if two heirs could claim one camp — they cannot (one camp per ruin, one pretender per ruin). Safe, but verify before moving it.

15. `heroes` VERSION 2 vs `story_web` VERSION 1 and the `heroes_revision` field: story_web copies the hero block's `policy_revision` so a consumer can tell which cast a web was compiled against, but there is no check that the two were generated in the same run. A stale `heroes` with a fresh `story_web` would compile silently. Consider a stronger binding in the port.

**`wells/guilds._order` remnant fallback object.**

When a beast-taken ruin's `evidence.nest_id` names no placed nest, the remnant org is built from the literal `{'family': 'beast', 'name': 'the beast'}`, so `charter.against` is 'beast' and `charter.nest_id` is null; the fallen champion's `nest_name` is the string 'the beast' and its claim target_name reads 'the beast, the doom of <short ruin name>'. The org's `home.kind` is 'ruin' (not 'city') and its `name` is 'the Order of <short RUIN name>'. The spec gives the org uid and kind but not the fallback family/name or the home kind.
